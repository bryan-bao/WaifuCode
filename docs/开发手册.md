# WaifuCode

桌面上站着一个二次元角色。她有心情、会出声，你能给她派活，她自己开终端跑 Claude Code，
**而且烧的是她自己的上下文，跟你正在用的那个窗口毫无关系。**

`models/` 里备了 **13 个形象**（12 个 Live2D 官方免费 sample + 用户自己加的海梦），
另外备着 6 身换的贴图。改 `config.json` 的
`modelPath` 换人，或者在设置面板里选（不用重启）。谁能做到什么、比例怎么量的，
见下面「[关于角色](#关于角色13-个人怎么加新的)」。

## 怎么启动

双击 `启动.bat`。

她会出现在桌面右下角，任务栏托盘里也有个图标。

## 怎么用

| 你想干嘛 | 怎么操作 |
|---|---|
| 找她说话 | **点她一下**，她会自己开口（看时间、看心情、看你手头有没有活） |
| **摸她** | **按住她的头别松手** —— 她会眯着眼往你手的方向蹭；摸太久会躲开 |
| **接着这句聊下去** | **点一下她头顶那个气泡** —— 跳到私聊窗口，刚才那句话已经在那儿了 |
| 派活 | **双击她**，或托盘右键 → 派个活 |
| 单独聊天 | 派活面板右上角「私聊」，或托盘右键 → 跟她聊聊 |
| **一起玩** | 右键 →「一起玩点什么」：猜情绪 / 猜歌 / 番茄钟（**都不花钱**） |
| 让她跳舞 | 在她身上右键 → 跳个舞 |
| 让她唱歌 | 右键 → 唱首歌（放的是你自己丢进 `music/` 的歌） |
| 摸头 | 点她脑袋（会脸红；**连着摸会烦**） |
| 换身打扮 | 右键 → 换身打扮（能换到什么程度看模型，见下面「关于换装」） |
| 挪位置 | 按住拖（她会「欸」一声，而且**不花钱**） |
| 菜单 | 在她身上点右键 |
| 静音 | 托盘右键 → 取消勾选「让她出声」 |

她的眼睛会**一直跟着你的鼠标**（不用鼠标压在她身上，满屏都跟）。
你停下不动超过八秒，她的视线会自己飘走 —— 一直用同一个角度死盯着一个不动的鼠标，
比压根不跟随还渗人。

### 派活面板

1. **项目目录** —— 点「浏览」选，或直接粘路径。用过的项目会变成小标签，下次点一下就填上
2. **要她做什么** —— 说人话就行，跟平时用 Claude Code 一样
3. 两种干法：
   - **让她后台干** —— 你该干嘛干嘛，她自己闷头做，做完气泡告诉你结果
   - **开终端我看着** —— 弹出一个真终端窗口，你能看着她干，随时插手接管

`Ctrl + Enter` 是派活快捷键。

面板中间那块「开着的终端」列的是**现在同时开了几个终端在干活**，每条带个呼吸灯：
绿的在跑、黄的在等你确认、灰的这轮完事了。**点一条就把那个终端窗口捞到最前面来** ——
开到四五个之后，一个个去任务栏里翻实在太痛苦。

**你把哪个窗口叉掉了，列表里那条就自己消失**，不用手动清。判据是终端里那个
`term-shell` 进程还在不在 —— 窗口被关它就跟着没了，几秒内列表就更新。
（探测用的是 `process.kill(pid, 0)`，那个 0 不是信号，什么都不发、
更不会去结束任何进程，纯粹是问一句「这个 pid 还在吗」。）

有个区别值得说清楚：**claude 干完活退出 ≠ 窗口关了**。活干完时窗口还开着
（停在「按回车关掉这个窗口」等你看结果），这条会变灰留在列表里，
你还能点它把窗口调到前面翻记录。等你真把窗口关了，它才消失。

桌宠自己重启也不会把列表弄丢：那些窗口还在按时报心跳，重启后会被一条条认回来。

#### 「−」收起来：任务栏按钮只在最小化期间存在

面板是 `skipTaskbar: true` 的浮窗（贴着角色，不该在任务栏占个位置）。
但**这个属性和「最小化」是天生冲突的**：直接 `minimize()` 之后任务栏上没有它的按钮，
你要么去 Alt+Tab 里翻，要么回去双击角色。那还不如直接关掉。

所以任务栏按钮做成了**只在收起来的那段时间存在**：

```js
// 收起来（顺序不能反）
panelWin.setSkipTaskbar(false);   // 先给按钮
panelWin.minimize();              // 再缩

// 展开时摘掉
panelWin.on('restore', () => panelWin.setSkipTaskbar(true));
```

Electron 的 `setSkipTaskbar` 底下就是 `ITaskbarList::AddTab / DeleteTab`，
不改窗口样式，所以来回切是干净的。

另外 `createPanel()` 里那条「已经开着就直接 show」的分支加了一句
`if (isMinimized()) restore()`。实测这版 Electron 的 `show()` 自己会恢复，
但**不保证会触发 `restore` 事件** —— 不触发的话任务栏按钮就一直挂着摘不掉了。
显式 `restore()` 一句话的事，别赌。

## 为什么不占你的上下文

每次派活，她都是**另起一个 `claude.exe` 进程**，工作目录设成那个项目：

```
claude -p "你交代的活" --session-id <该项目专属UUID> --permission-mode acceptEdits
```

> **「让她后台干」开的是一个最小化的真终端，不是无头进程。**
>
> 换掉无头模式的理由只有一条，但很硬：**跑挂了你看不到现场**。无头模式只能从
> stream-json 里捞一句摘要 —— 栈、上下文、她当时试了什么、卡在哪个确认上，全没了，
> 你连查都没得查。
>
> 最小化的终端两头都占：不往你脸上弹，但滚屏全在。想看现场有三条路：
> 在她身上**右键 →「看看她在干嘛」**、点面板「她手上的活」里那条、
> 或者**直接点她汇报时冒出来的那个气泡**（那种气泡点了是调终端，不是跳私聊）。
>
> 实现上跟「开终端我看着」走的是同一套，唯一差别就是 `minimized` ——
> **两种派法开出来的窗口长得一模一样**（都是 wt），后台那个开完立刻收进任务栏。
>
> **露脸约 250 毫秒，躲不掉。** wt.exe 没有「最小化启动」这个开关
> （`wt --help` 里只有 `-M/--maximized`、`-F/--fullscreen`、`-f/--focus`、`--pos`、`--size`、`-w`），
> 而 `start /MIN` 也管不到它 —— wt.exe 只是转发器，真窗口由 WindowsTerminal.exe 建。
>
> 两条试过但**行不通**的路，记下来免得再走一遍：
>
> **① `wt --pos 30000,30000` 开到屏幕外。** wt 会把坐标**夹回桌面范围内** ——
> 实测两块 1920 的屏，30000 被夹成 1912，窗口照样全露着。
>
> **② 先起最小化监视器、再开窗口**（想让 PowerShell 的 `Add-Type` 编译跟 wt 启动并行）。
> 反而**糟十几倍**：露脸 5.2 秒 vs 0.25 秒。监视器起太早会抓到一个中间态窗口、
> 把它收掉，真窗口出来之后就一直露着。**顺序必须是「先开窗口，再起监视器」。**
>
> 这两个数都是量出来的：高频采样窗口的「可见且未最小化」时长，不是估的。
>
> 想换回无头：`config.json` 里 `"dispatch": { "mode": "headless" }`。

- **一个项目 = 一条独立会话**，UUID 记在 `sessions/registry.json` 里
- 同一个项目再派活会 `--resume` 接上，所以她对每个项目**有连续记忆**
- 但这些会话跟你手头这个 Claude Code 窗口彻底分开，各烧各的 token

权限用的是 **auto**：让 claude 自己用分类器判断，安全的放行、危险的拦下，
两边都不用等人。（`claude auto-mode config` 能看到规则，`auto-mode critique`
还能让它帮你审自己写的规则。）

早先用的是 `acceptEdits`，那个只自动放行文件编辑 —— 她要跑个 `npm test` 照样卡在
那儿等确认，后台任务就白瞎了。但也绝不给 `bypassPermissions`，那等于把整台机器
交出去。想改回去：`config.json` 里 `"dispatch": { "permissionMode": "acceptEdits" }`，
终端任务是 `"terminal": { "permissionMode": ... }`。

## 哪些花钱，哪些不花

这事值得单独说清楚，因为差别很大：

| 要调 claude（花钱） | 不调（不花钱） |
|---|---|
| 后台派活 | 心情状态机 |
| 终端任务 | 情绪台词（写死的台词库） |
| 私聊，一句约 **5 分钱** | **跳舞本身**（纯正弦波算参数） |
| | **一起玩那三个玩法**（题目和反馈全本地生成） |
| 点她时她主动搭话，一次约 **1 毛** | 放歌、测 BPM |

> **这两个数字改过。** 原来写的是「私聊 2 分、搭话 1~2 分」，那是估的。
> 翻了 43 小时的真实日志：搭话 39 次 $0.59（均值 **$0.0151**）、私聊 17 轮 $0.14
> （均值 $0.0084）—— 搭话比原来写的**贵五到十倍**。
>
> 单次成本拆开是：缓存写 56%、输出 40%、缓存读 3%。所以**省钱的主战场是让
> system prompt 逐字节稳定下来吃缓存**，不是让她少说话，更不是换个便宜模型 ——
> 实测 Haiku 配 `--json-schema` 会翻车：为了凑出结构化结果吐了 3400 个
> output token（Opus 只要 221），40 秒、$0.019，**又慢又贵还更笨**。
| 她决定跳什么舞（跟回复一起出来，不额外收费） | 语音合成（微软 Edge 免费接口） |

一句话：**「她说什么」要调 claude，「她怎么动」不用。**
所以她跳一整天舞是零成本，但每讲一句新鲜话都要花钱。

> **上面那两个数字是「她自己说话」的成本，不是大头。** 真正的大头是你派出去的
> 终端里那个 claude —— 一场长的开发会话轻松几十美元，比搭话高两个数量级。
> 那笔账现在也能看见了（面板上每条线一个金额），怎么算的见
> 「[终端里烧了多少钱](#终端里烧了多少钱srccostjs)」。

私聊和主动搭话都关掉了设置源（`--setting-sources ""`），
省下一大坨系统提示词 —— 实测一轮从 $0.014 降到 $0.002。

> **踩过的坑：`turns > 0` 不等于「上次那条会话还在」。**
> registry 里的 turns 记的是**开过几次**，不是**会话真的建立了**。
> 而交互式会话要正常退出才落盘 —— 窗口被直接叉掉就什么都没留下。
> 于是 registry 上写着聊了 6 轮，磁盘上一条都没有，下次一 `--resume`
> 终端窗口开出来就只有一行红字：
>
> ```
> No conversation found with session ID: c5026c88-…
> ```
>
> 现在改成去 `~/.claude/projects/` 底下**实地看一眼**那条会话在不在
> （目录名是把路径里的冒号和斜杠都换成横线：`E:\chao-tool\VideoTool`
> → `E--chao-tool-VideoTool`），不在就换个新 id 重开。
> `hooks/term-shell.js` 里还留了一道保险：万一还是接不上，它自己拿同一个 id
> 开条新的重来，不把红字甩给你。
>
> 顺带一提：**想让她记住这次聊的，用 `/exit` 退出，别直接叉窗口。**

## 会话丢了怎么查

```
npm run sessions
```

会话丢失是这个项目里**最难自己发现**的故障：她不报错，只会安静地换条新会话重开
（`sessions.js` 的 `_resumableRecord`）。从外面看就是「她突然不记得之前的事了」。

这个命令逐个项目告诉你 registry 记的那条会话还在不在，以及**同一个项目下还有没有
她开过的别的会话可以接回来**（判据是会话名以 `waifu:` 开头 —— 你自己开的会话不会被碰）。
能接回来的话它会告诉你怎么改 `registry.json`。

丢失的两个常见原因：交互式会话直接叉窗口（不落盘），或者超过 30 天被自动清理了。

### 私聊那条会话丢了会怎样

私聊有**两层记录**，丢了一层不影响另一层：

| 哪一层 | 存在哪 | 管什么 | 留多久 |
|---|---|---|---|
| 你看得见的聊天记录 | `sessions/chat.json` | 窗口一开铺回界面上的那些字 | 最近 300 条 |
| 她脑子里的记忆 | `~/.claude/projects/…/<uuid>.jsonl` | 她记不记得你们聊过什么 | 30 天，或被清理 |

第二层没了的话，`--resume` 会撞上 `No conversation found`。这在私聊里比派活恶劣得多 ——
派活是你主动点一次才发生，**私聊是你每说一句撞一次**，会永远卡在那句报错里出不来。

所以 `chat.js` 的 `_resumeState()` 每次说话前先去磁盘看一眼，不在就换条新的重开，
并且**把界面上还留着的最近三轮垫进新会话**（第一层是好的，白白扔掉可惜）。
你的感受是「她好像忘了前天聊的」，而不是一直报错。垫背景这件事她不会说出来。

> 极少数情况文件在、claude 却不认（存档损坏）。这种预检拦不住，
> 就在失败时把 id 作废掉、提示你再说一句 —— 没有原地重试，因为再起一个进程要几十秒，
> 让她卡着不动比报一句话更难受。

> **踩过的坑：`-n` 会把你 `/rename` 改的名字冲掉。**
>
> `-n` 设的是会话的 `customTitle`，而 `/rename` 改的**正是同一个字段**。
> 原来开终端和派活都无条件传 `-n waifu:项目名`，于是你在终端里
> `/rename` 改好的名字，下次她再开这个终端就被冲回去了。
>
> 实测（同一条会话连跑三次）：
> ```
> --session-id … -n 名字甲   → customTitle = 名字甲
> --resume …     -n 名字乙   → customTitle = 名字乙   ← 覆盖了
> --resume …     不传 -n     → customTitle = 名字乙   ← 保住了
> ```
> 现在改成**只在新开会话时给名字**。不传也不会丢终端标题 —— claude 会沿用
> 会话里已有的 `customTitle` 去设，桌宠照样按标题找得回窗口。
> 当初担心的「标题被冲掉」只发生在首次创建（那会儿会话还没名字）。

## 终端开的是 Windows Terminal

以前用的是 `start cmd`，开出来是那个灰白色的老式控制台 —— 因为这台机器的
「默认终端应用」被设成了传统 conhost，`start` 就老老实实地把它请了出来。

现在直接点名 `wt.exe`：深色、现代、字体正常，每个任务一个独立的具名窗口
（`waifu-w1`、`waifu-w2`…），这个名字就是后面能把它精准捞回前台的凭据。
没装 Windows Terminal 的机器会自动回落到老式控制台，功能不受影响，就是难看点。

想强制用老式控制台：`config.json` 里 `"terminal": { "app": "conhost" }`。

> **踩过的坑：`fs.existsSync('wt.exe')` 会骗你。**
> Windows 的「应用执行别名」（`wt.exe` 正是其中之一）是个 93 字节的 reparse point，
> 权限特殊，`statSync` 跟过去直接 EACCES，于是 `existsSync` 一口咬定文件不存在 ——
> 明明 `where.exe` 找得到、也能跑起来。得用 `fs.accessSync(p, F_OK)`，
> 它只问「在不在」，不跟过去。

> **踩过的坑：别把命令直接摆到 wt 的命令行上。**
> 那样至少有三个带空格的东西要过 wt 的解析器（node 路径可能是
> `C:\Program Files\nodejs\node.exe`、脚本路径、项目路径），拆断一个就全废。
> 改成先写一个 `.cmd` 启动器，wt 那边只需要认一个可执行文件路径，
> 翻车面小了一大截。顺带在启动器里 `chcp 65001`，不然中文全是乱码。

## 窗口关没关，三条探测路

「面板上那条什么时候暗下去」曾经只靠一条腿：`_sweep` 每 3 秒一拍的 pid 探测
（`process.kill(pid, 0)`）。它有个 Windows 特有的坑：**pid 是回收复用的** ——
term-shell 一死，号码可能立刻发给别的进程，探测就一直误报「还活着」，
面板上那条要挂到接盘的进程也退出才消失（实测挂过好几分钟）。
用户看到的就是：窗口关了，列表里它还亮着，点一下提示「按标题没找到窗口」。

现在是三条腿，全汇到 `_windowGone()`：

| 路 | 延迟 | 原理 |
|---|---|---|
| **gone（亲口报）** | 亚秒 | 窗口被叉掉时 Node 收到 SIGHUP，系统给 ~5 秒收拾后事；term-shell 抢在死前发一记 `{phase:'gone'}`（1 秒超时的本地 HTTP）。按回车正常退出那条路（hold）也发 |
| pid 探测 | ≤3 秒 | 原来那条，gone 没发出去时兜底 |
| **心跳断了** | ~25 秒 | term-shell 每 5 秒一跳（`rec.lastBeat`）。断超 16 秒**且连着三拍**都断着才判死 —— 「连着三拍」是给睡眠唤醒留的余量。这是 pid 被复用时唯一的出路 |

## 派活选模型

面板上那个「用哪个模型」下拉，值走白名单（`main.js` 的 `DISPATCH_MODELS`）——
这个值最终拼进命令行（term-shell 的 `--model`），收任意字符串等于让面板往
命令行里塞参数。**选一次就持久化**（`config.dispatch.model`），面板派活、
右键菜单派活、headless 三条路都认它；主进程按「opts 里有没有 model 这个键」
区分「面板明确选的」和「老入口没这回事」，后者回落到记住的默认值。

## 派活还能选 Codex（CLI 适配层）

### 陪聊也能走 codex（私聊 + 搭话）

「用谁来干」选了 codex 时，chat.js / greet.js 各自分岔到 `_sendCodex` /
`_greetCodex`（claude 原路一个字没动）。下面这些全是**实测**出来的
（2026-08-19，codex 0.147.0），别按想象改：

- `codex exec --json` 第一行 `thread.started` **直接给会话 id** ——
  陪聊不用像派活那样去档案里认领；`codex exec resume <id>` 真的记得上文。
- **没有 --system-prompt 那种换底的口子**：`-c base_instructions=...` 被
  **静默无视**（session_meta 里还是原装的 You are Codex）。人设只能每轮垫在
  开场白里 —— 实测压得住身份（自称小依，不自称 Codex），心情每轮在变，
  每轮都带反而是对的。
- `exec resume` **不认 -s / -C**（exit 2），沙箱走 `-c sandbox_mode=read-only`
  （不带引号：TOML 解析失败按原样字符串收下，help 明说；引号过 .cmd 的
  shell:true 会被 cmd 啃掉一层）。
- **prompt 一律走 stdin**（参数表最后那个 `-`）：人设+聊天内容是多行自由文本，
  绝不过命令行（term-shell 同一个坑）。
- 搭话的 JSON **靠提示词要，不用 --output-schema** —— 实机踩过（2026-08-21）：
  走中转（relay）的 codex 对带 schema 的请求一律 502、重试五次耗满 55 秒，
  搭话全军覆没；去掉后同一句 5.4 秒就回。表情名单（SCHEMA 的 enum）直接列进
  提示词。解析放宽（答复里抠第一个 { 到最后一个 }）—— 解不出返回 null
  回落本地台词，跟 claude 侧一个约定。
- 算钱：`turn.completed` 带用量，模型从她自己的档案里认（`codexModelOf`
  抠头 **512KB** —— 第一轮会把人设/技能说明整段回显，实测第一个 model 字段
  在 68KB 开外，64KB 的头刚好错过，踩过）。认不出按旗舰报高。
- 成本量级要有数：codex 陪聊一轮折算 ~$0.05（行头两万多 token），claude 那条
  `--setting-sources ''` 的路一轮 ~$0.008。订阅用户不真扣，账面如实。


面板上「用谁来干」下拉（claude / codex），给没装 Claude Code、装了 Codex CLI 的
机器用。架构上的要点：**窗口那套（开/关/心跳/gone/pid/任务栏标题/置顶让位）全在
我们自己的壳 term-shell 里，跟里面跑什么 CLI 无关，一行没动**。真正分岔的只有两处：

- **参数怎么拼、bin 在哪** —— 收在 `src/agents.js`。term-shell 按 `spec.agent`
  分支去 require 它（打包是 asar:false，src/ 在真实磁盘上）；这个文件**只许用
  node 自带模块** —— term-shell 是另起的 node 进程，碰 electron 就起不来。
- **hook 那一挂 codex 没有，但汇报补上了（三期）** —— 它的会话档案是**实时**
  写的，每轮结束都有 `task_complete` 事件，而且 `last_agent_message` 就是
  她这轮最后说的话（claude 那边费劲从 Stop 事件里拿的东西，这儿白送）。
  `_codexWatch` 跟着 _sweep 的 3 秒节拍盯档案，一轮干完先 emit('turn')
  （流水的按轮统计靠它，不发的话 codex 在日/月摘要里永远是 0），再 emit
  **跟 _report 一模一样形状**的 report 事件 —— main 那头的语音、气泡、小抄、
  流水、心情一行没改全接上了。工具数（function_call/custom_tool_call）、
  改过的文件（apply_patch 的 *** Update File:；function_call 形态的 arguments
  是没解码的内层 JSON，**先 parse 再抠**，直接跑正则会把整段补丁吞成一个
  「文件名」）、报错（error 事件）、用户这轮说了什么（老版 user_message /
  新版 role=user 两种形状都认）一并从档案里读。
- **盯档案必须是增量读（字节偏移 + 半行保护），不是整读减基线** ——
  整读出来的是累计值，档案超 8MB 被截尾后计数不再单调，「绝对值-基线」
  当场塌掉（长会话汇报永久停摆，评审抓的）。增量读每拍只解析新长出来的
  字节，量出来的天然是「这一段」的（claude 每轮 UserPromptSubmit 清零同义）；
  偏移只停在行首，半行留给下一拍。工具/报错/文件在轮内先攒在 codexCarry，
  task_complete 一到连攒的一起报。粗筛用带右引号的字符串（"type":"function_call"
  撞不上 …_output，转义过的嵌套文字也撞不上），parse 完再核对 payload.type。
- **盯档进度和已入账的钱要落盘**（`_codexPersist`：spec.codexSeen =
  偏移/报到第几轮/最后那句，spec.costPaid）—— 不落的话桌宠重启 _adopt 认回来：
  刚报过的那轮**原样重播一遍**（气泡+语音+小抄+流水各一份）、已结的钱在流水里
  **再记一遍**（评审抓的两条 high）。只在轮结束时写，3 秒节拍的中途不写。
  新认领的文件从偏移 0 跟起（认领前就干完的快轮不丢）；接着聊（expectId）认到
  的新文件可能抄了旧对话，从当前末尾跟起。
  仍然缺的只有**护栏** —— 那要在动手**之前**报警，档案是干完才写的，拦不了。
  「干完了」照旧走壳层 `child.on('exit')`。

几条容易踩的：

- **权限映射宁紧勿松**：claude 模式名 → codex 的 -a（问不问）+ -s（沙箱多严）。
  `--dangerously-bypass-approvals-and-sandbox` 和 danger-full-access **永远不映射**，
  test-agents 第 2 节钉着。
- **codex 不收外派的会话 id，会话是事后「认领」的**。它开局就往
  `~/.codex/sessions/YYYY/MM/DD/rollout-<时间>-<uuid>.jsonl` 落一份，第一行
  session_meta 带 cwd。`_codexPeek` 跟着 _sweep 的 3 秒节拍、**窗口活着就
  一直配**（不设截止 —— 原来的 90 秒窗实机死过：空任务终端的 rollout 要等
  用户敲第一句才落盘，w63 差一秒错过后整条线静默全灭），按三道闸配对：
  文件创建时间 >= 启动时刻、cwd 就是项目目录、uuid 没被别的线认领。
  开窗 90 秒之后的「晚认领」多一道**新鲜度闸**（只认 10 秒内还在写的档案）——
  不设的话已出列死线的旧档案会被捡走：汇报重播 + 已入账的钱二次入账。
  认领到手回写 spec 文件（重启 _adopt 才找得回）+ 记到 lane 上
  （rememberCodexSession）。「接着聊」就是 `codex resume <uuid>`（resume 是
  **子命令排最前**，-a/-s/-m 照吃，实测过）；接着聊不拼小抄 —— 会话里上下文
  本来就在。真空窗（文件系统层面分不出来、认了的）：同目录**同时挂着两条以上
  没认领的空任务窗**时，谁先手谁认走刚落盘的会话 —— 后开的窗敲的第一句可能
  被先开的认走（认领时日志里会大声记一笔）；用户自己在同目录手开 codex 同理。
- **codex 的钱：只认 rollout 里最后一条 token_count**。它带的是**累计**用量
  （total_token_usage），整读一遍取最后一条完整的就是全部 —— 不用 cost.js
  那套字节偏移增量，天然不怕重复计；半行 JSON.parse 抛错就往上找上一条。
  单价表（agents.js 的 CODEX_PRICE，查于 2026-08-18）：缓存命中一折、
  **缓存写不要钱**（跟 Anthropic 的 1.25×/2× 是两套规矩，别照搬 cost.js）、
  认不出的模型按旗舰 $5/$30 报高、mini/nano 走小档。窗口成本 = 当前累计 −
  codexBase 基线 —— **基线记 token 不记美元**：接着聊续写同一份文件、中途换过
  模型的话，记美元会两头价目不一致，差值被压成 0（报低，不许）；差值按当前
  模型定价。同一条线关了再开，上一窗口 settle 过的钱不会再算一遍。
- **评审又抓出来的五个坑（都修了、都有自检钉着）**：
  ① 日期目录**三天都得翻**（昨天/今天/**明天**）—— 23:59 派活、codex 零点后
  落盘进「明天」的目录，只往回翻就永远认领不到，而且是静默的。
  ② **接着聊的窗口带 expectId 去找，只认自己那条** —— 不设这道闸，它 90 秒里
  会把同目录新开线刚落盘的会话抢走（新线还没认领、id 不在 claimed 集里）。
  ③ **codexClaimed 要落 spec** —— 不落的话桌宠重启 _adopt 认回来会重新开抢
  重新开抢，能把已经对的绑定改成别人的会话。同目录两条新线**晚开的让早开的先认**
  （让先只让 90 秒 —— elder 拿不到就轮到 junior 自己认）。
  ④ **codexUsage 读失败返回 null，不是 usd:0** —— 杀毒/备份短暂锁文件是真事，
  读失败那一下把算好的数抹成 0，之后 mtime 不再动，关窗就按 0 结算了。
  ⑤ **dispose 时把 codex 线没入账的钱结掉** —— 它只有关窗一个结算点，
  用户先退桌宠、窗口后关的话整窗的钱一分都进不了流水；claude 线每轮汇报
  都结过，只丢尾巴，codex 丢的是 100%。另外已关的线不再刷新金额
  （接着聊的新窗口在续写同一份文件，再刷会两条线各涨一遍）。
- **小抄没参数可传**（claude 走 --append-system-prompt-file），改成拼进开场
  prompt，而且**只在真派了活的时候拼** —— 没任务却递 prompt 等于替用户开跑一轮，
  花的是他 OpenAI 的钱。
- **cmd 的命令行里换行没有转义写法**，包进引号也会被当成第二条命令。quoteArg
  现在把换行折成空格（只影响 .cmd 安装走 shell:true 的批处理路；.exe 安装
  shell:false 原样透传）。这顺手兜住了 claude 多行任务在 .cmd 安装上的老隐患。
- **关窗去留**：codex 线收不到 hook，turns 恒 0 —— `_windowGone` 的 keep 条件
  补了「codex 且派过活**且真起来过**（有 pid 或打过心跳）」。少最后半句的话，
  term-shell 压根没报到的夭折线会冒充「已完成」骗出「再来」。
- **「再来 / 接着聊」带的是那条线自己的 agent，不是面板此刻选的。** 第一版
  「接着聊」没带 agent，回落到记住的全局默认 —— 你切过一次 codex 之后，
  claude 老线会被当成全新 codex 会话打开，明明能 --resume 的记忆静默丢掉。
  同理「再来」不带 model 键（主进程回落记住的默认）：面板停在 codex 档时
  模型下拉是被清空的，带出去会把记住的模型洗掉。
- **agent 的「记住」在面板下拉 onchange 里做（saveSettings），派活入口不落盘。**
  原来在 resolveDispatchAgent 里 patch：没装 codex 的机器上被 guard 拦下的
  那次尝试也会把 'codex' 写进 config，之后所有不带 agent 字段的入口全撞
  「没找到 Codex」。先落盘后 guard 就是这么埋雷的。
- codex 线**不传 -m**：它不认 claude 的模型名，模型跟 ~/.codex/config.toml 走。
  面板上选 codex 时模型下拉灰掉；切回 claude 时把你记住的那个模型还回去
  （不还的话摸一下 codex 就把记住的模型洗没了）。

改这块跑 `npm run test:agents`（离线，几百毫秒），端到端想验就照
scratchpad 里那招：假 codex.cmd 把收到的 %* 写进文件，跑真 term-shell 对答案。

### 「帮我装」：CLI 没装时她自己 npm -g 装

guard 拦下时结果里带 `missing: 'claude'|'codex'`，面板据此在报错旁长出
「帮我装」按钮 → IPC `agent:install` → main.js 的 `installAgent()`。
三个实测过才写下的点：

- **必须 `shell: true`**：npm 在 Windows 上是 .cmd，新版 node（CVE 修复后）
  不带 shell 直接 spawn 它会 EINVAL。给的是裸名 `'npm'`（onPath 先确认过在），
  躲开 `C:\Program Files\...` 里的空格在 shell 拼接时炸掉。
- **装完不用重启**：新命令落在 npm 全局 bin，那个目录本来就在 PATH 上
  （npm 都在了它必在），下一次 guard 探测直接就能过。老提示里的
  「装好后重启一次桌宠」是错的，已删。
- **本进程的 PATH 是启动时冻结的**，两处都得认账（评审抓的）：
  ① 没 npm 的分支不能说「装完回来再点」—— 用户装完 Node 本进程照样看不见，
  文案明说要重开桌宠；② npm 退出码 0 不等于 guard 下次探得到（全局 prefix
  挪过、目录不在 PATH 时照样落空），播「装好啦」之前回头跑一次
  codexInstalled()/claudeInstalled()，探不到就改口说实话，不发喜报。
- 包名钉死在 `AGENT_PKG`（@anthropic-ai/claude-code / @openai/codex），
  **test-agents 第 18 节逐字守着** —— 打错一个字就是把用户机器交给 npm 上的
  同名钓鱼包。10 分钟装不完就 kill + 解锁（shell:true 下杀的是 cmd 壳，
  里面的 npm 可能还活着，只影响提示，不值得上进程树）。同一时刻只装一个。
  装完/装砸都走 `session:say` 开口 + 广播 `agent:install-done`
  （面板关着也听得见）。登录（claude / codex login）是浏览器授权，替不了。

## 更新安装的「无法关闭」（2026-08-26 实机排查）

装新版时 NSIS 反复弹「WaifuCode 无法关闭，请手动关闭后重试」，手动关了
也没用。扒了 electron-builder 的 NSIS 模板 + 本机逐步复现它的杀伤链：

- 它先温柔 taskkill（发 WM_CLOSE）→ **对托盘应用无效**（实测 4 个进程
  一个不死：窗口关了、进程还在）→ 再 taskkill /f 强杀 → 实测 2 秒内全清。
  所以正常情况根本弹不出那个框。
- 弹出来 = 进程**连 /f 都杀不掉或一直复活**。最可疑的一条链：
  `before-quit` 里那串 dispose 原来**没有逐个兜异常** —— 任何一步抛出去
  就是主进程未捕获异常 → Electron 弹原生错误框 → **进程僵在弹窗后面
  永远不退**，而那个错误框还常被安装器窗口挡住，用户只看到怎么都关不掉。

**【最重的一雷】升级会把 $INSTDIR/data 连锅端**：electron-builder 升级时执行的
是**旧版装的那个卸载器**（注册表翻出来的老程序），收尾 RMDir /r $INSTDIR ——
用户存档全灭，且表现只是「桌宠重新认识你」，没人会报 bug（金丝雀实测阵亡
两轮才定位）。修法三层：customCheckAppRunning 里把 data 备份进 $PLUGINSDIR
（顺手抄旧版 package.json 当「从哪版升上来」的条子）→ customInstall 放回 →
customRemoveFiles 顶掉默认连锅端（保 1.0.3+ 装的机器 + 真卸载也留 data）。
条子的读取端在 main.js：**路径是 exe 旁的 data，不是 ROOT**（打包后 ROOT 是
resources/app，差两层，踩过）。最严苛验证：装回带旧卸载器的 1.0.2 → 种金丝雀
→ 新包升级 → 数据活、条子对。

**第三刀在安装器里**（build/installer.nsh，nsis.include 挂进去）：弹框逻辑
跑在**新安装包**里，所以把 electron-builder 的 customCheckAppRunning 换成
「温柔一刀 + 强杀两刀（间隔留足收尸时间）+ 永不弹框」—— 老版本升上来那一跳
用的就是新安装器，也跟着好了。默认那套的死穴：强杀后零间隔就复查，Electron
四个进程收尸没那么快 → 误判「关不掉」。桌宠没有「没保存的文档」，直接请走。

两条修法都上了（`tools/test-update.js` 钉着）：

1. `before-quit` 每步各自 try（跟 settings:save 的 step() 同一课）。
2. 更新退场不再 `app.quit()` 等 2.5 秒 —— 手动把该收的收了（隧道/两个
   服务/会话/终端/聊天/心情/语音，每步兜住），最后 `app.exit(0)` 一刀切：
   它不走事件链，没有任何东西能拦住它。1.5 秒后执行，气泡来得及露脸，
   安装器要人点几下才走到检查那步。

**更新说明要摞历史，不许覆盖**（release-notes.json 现在带 history，封顶
10 版）：用户可能隔几版才更新一次，只留最后一版的话中间的大功能说明全丢。
摞/换/选的规矩在 `updates.mergeNotes / notesSince`（纯函数，test-update
「跳版补显」一节守着）。弹窗换成了排版窗口（renderer/notes.html，数据走
loadFile 的 query，零 IPC 零 preload）：按版本分段带日期，每版里
`classifyNote` 按提交信息关键词分「新增 → 修复 → 优化」三组 ——
**提交信息以「修：」开头必进修复区**，功能措辞五花八门所以兜底进新增，
合并/整理/文档类进优化；收集时 `--no-merges`（中文「合并 xx」正则挡不住）。
条目进 innerHTML 前必须过 esc()。

另外「检测不到」九成不是代码：分发服务跟着发包机的桌宠走（桌宠关了就没
了）、DHCP 换 IP、发包机防火墙拦 electron 入站。面板现在打开就触发一次
checkUpdate（app:info 那条 IPC 顺手查），不用等开机 20 秒那班车。

## 静默失效那一类坑（2026-08-25 排查，务必读）

起因：registerHotkey 定义在 createTray() 内部，设置保存那条路在 wireIpc() 里
调它 —— ReferenceError 被 handler 的 try/catch 吞掉，**值存进去了、键没重挂**，
用户看到「保存成功但按了没反应」。顺着这个形态扫了一遍 main.js，同类的还有：

- **cost 从没 require 过**却在 session:lanes 里用（给没名字的线取名）——
  一碰到没名字的线就抛，被 catch 吞成空数组，**整排「留着的线」静默消失**。
  短路求值让它时灵时不灵：线都有名字时一切正常。
- **claudeBin 只在启动时解析一次**，terminals/chat/greeter 各存一份 ——
  「帮我装」装完她说「再点一次就能开工」，实际还是 spawn ENOENT，得重启。
  装完要把新路径推给那三摊（codex 那条不受影响：它每次现解析）。
- **只在开机读一次的渲染层开关**（gesture/marks）：改了不重载 = 存档对了、
  行为没换，跟快捷键一模一样的形态。
- **一个 try 罩住写盘和所有生效步骤**：盘早写了，后面任一步抛就报「没存上」，
  而且排在抛点后面的步骤一件不做。现在每步各自 step() 兜住。

**三条经验**：① 嵌套函数别跨作用域调（test-wiring 第 8 节钉着，node --check 查不出）；
② catch 里至少 log 一行 —— 空数组/null 跟「读挂了」在协议上分不开；
③ 「启动时读一次」的东西，配置改了就得有人负责让它重读。

## 截图（src/shot.js + renderer/shot.html）

快捷键（hotkey.shot，**默认留空**，用户自己在设置里按一个）→ 每块屏各盖一层
透明浮罩拖框 →
**先把浮罩 destroy 掉再等 120ms 才拍**（不然拍到自己那层灰罩）→
PowerShell 的 CopyFromScreen 抓原生像素 → 存 data/shots → **写进剪贴板**
（`clipboard.write({ text: 路径, image: 位图 })`），用户自己 Ctrl+V 粘到哪儿是哪儿。

几条不许退的：

- **一块屏一层浮罩，不许拿并集开一个大的。** 双屏机上量的（2026-08-25）：
  要 3840x1080，Windows 只给 **1920x1032** —— 它把窗口裁到了「一块屏的工作区」
  （1032 = 1080 减任务栏）。第二块屏根本没被盖住，用户的说法是
  「双屏只能截当前这块」。而且 **show 完还得 setBounds 掰一次**，
  否则屏幕最底下那条永远框不到（同一个工作区裁剪）。
- **坐标要先加浮罩原点，再 dipToScreenRect。** 浮罩报的是**窗口内**的 CSS 像素；
  第二块屏那层的原点是 (1920,0)，不加就全按主屏算 —— 在副屏框，截回来的是主屏
  同样位置那块。原点必须在 destroy **之前**取（关了就问不出它在哪块屏上）。
  换算这一步也不能省：CopyFromScreen 要物理像素，缩放 125% 的机器上不换算就截歪截小。
- **别用 desktopCapturer**：它给的是缩略图，字会糊 —— 截给 AI 看的图糊了等于白截。
- **不许替用户发进终端。** 第一版是截完 `sendText` 打进「最近那条活线」，
  用户当场否了（2026-08-25）：他要的是**可粘贴**，粘进哪个框、配什么话、
  什么时候发是他的事；而且「最近那条」本来就是猜的，猜错等于把图贴给了别人那条活。
- **只放位图 = 等于没放**（第二版又栽了一次，同一天）：终端的 Ctrl+V 走的是
  「粘贴**文字**」那条路（Windows Terminal 自己就把这个键占了），剪贴板里
  只有位图时它拿到的是空的，**按下去毫无反应** —— 用户第一反应是「这功能坏了」。
  所以 `clipboard.write({ text, image })` 两个格式一起放：文字是路径（终端粘得进，
  发出去她自己去读图），位图是给微信/文档那边的。路径带空格要加引号。
  位图读不回来时才退成只有路径。`tools/test-shot.js` 第 3 节钉着这条
  （`!seg.includes('terminals.sendText')`）。截图攒多了自己清（留 40 张），
  只删自己截的那些。

详情页的历史：内存里的 rec.timeline 只有「这轮开的窗口」才有 —— 重启过、

同句去重）。**journal.add('report') 必须记 termId**，不记就没法按线捞。

第二批加的三样：

- **详情页 + 追问**：rec.timeline（内存，留 60 条，不落盘）在 _timeline() 一处
  记账，四个埋点（你说/她汇报/报错/等确认）。追问走 `sendText()`：
  **文本必须走剪贴板**（ps1 的 -PasteStdin）—— SendKeys 发不了中文，而且
  {}()+^%~ 在它语法里全是控制符；粘完把剪贴板还回去。安全线跟放行同款
  （-Exact + 回执标题核对）。
- **翻文件夹**：main 的 browseDirs()，**只列目录名、绝不读文件内容**，
  像项目的（有 .git/package.json）排前面。手机上没系统选择器，这是唯一解。
- **出门模式**：src/tunnel.js 起 cloudflared quick tunnel（不要账号/服务器），
  从 stderr 里抠 trycloudflare.com 网址。没装就现下（落数据目录，不进 C 盘）。
  **默认关、不持久开、退出必收**（stopTunnel 挂在 before-quit）——
  公网口不该在用户不知情时开着。

**跟 PowerShell 之间那两根管子，两头都必须走 base64**（2026-08-25 实机踩的）：

- 进：node 发 UTF-8，PS 的 [Console]::In 按 GBK 解 —— 「中文测试」变 6 个怪字
  进剪贴板，贴进终端就是用户看到的乱码。改走 -PasteB64。
- 出：PS 写 GBK 字节，node 按 UTF-8 读 —— 标题里的「·」当场坏掉，跟 rec.title
  比对必然不等，追问/放行被自己的安全闸拒死（日志里「跟这条线对不上」就是它）。
  所以 ps1 额外打一行 TITLE64，node 只认那行（sentTitle()）。
- 这个坑**极具迷惑性**：stdin 那条来回各错一次会「看起来正常」（我第一次验证就
  被骗过）—— 验证必须看**终端里实际执行的内容**，不能看回显。

SSE 穿公网那层会被缓冲：手机页**不许把身家性命押在长连接上** —— 进页面先拉一次
/api/state，8 秒没收到推送就退回 3 秒轮询（右上角「实时」/「在线」如实说）。

两条安全线是评审抓出来的，改这块前先读：

- **title 汇口必须杀控制字符**（terminals.js 的 lane 那行）。这条 title 会被
  _writeLauncher 逐行写进 .cmd 交给 cmd 执行，夹一个 CRLF 就能在**沙箱外**
  多跑一行任意命令 —— 手机 /api/dispatch 收 laneName，一路只 trim 就到这儿。
  堵在汇口（桌面/手机/右键所有派活都过这条），别在各入口各堵一次。
  test-mobile 第 7 节拿真实攻击载荷钉着。
- **发键必须 -Exact**。focus-window.ps1 精确匹配落空时会退回「标题包含」，
  而 Claude 跑起来会改标题、主线标题又是分线标题的前缀 —— 兜底会抓到
  分线窗口，把确认键敲进别的线。发键这条路禁用兜底，回执标题还要跟
  rec.title 严丝合缝（双保险）。真机验过：包含型窗口 NOTFOUND 一个键不发，
  精确标题 SENT 且命令真执行。

## 局域网版本更新（src/updates.js）

没有服务器：发包机开分发开关，node 自带 http 起只读服务（0.0.0.0:47200），
只认两个 GET —— `/latest.json` 和 `/<安装包文件名>`。latest.json 是**现场
从分发文件夹算出来的**（挑文件名里版本最高的包 + sha256，按 路径|大小|mtime
缓存哈希，几十上百 MB 的包不能每个请求重算）。收包机把 source 填成发包机
地址，开机 20 秒 + 每 4 小时查一次；有新版 → 面板 #ver 变按钮 + 她开口
（`update.announced` 挡着同版本只喊一次，settings:save 会先剥掉快照里的
announced 免得旧值把这笔冲掉）。点更新 → 下载到 data\update-download →
sha256 对不上**删包报错**（半个包比没有包危险）→ shell.openPath 拉起
NSIS → app.quit 让路。

更新说明弹窗：pack.js 在版本步之后从 git 提交标题收集（.pack-state.json 记
上次打到哪个提交，第一次取最近 15 条），写 release-notes.json 随包发布（两个
文件都 gitignore，.pack-state 还要进打包排除）。收包侧 main 启动时比
update.seenVersion 和当前版本：**升级上来才弹**（全新安装 seenVersion 为空，
只默默记下）；settings:save 会把快照里的 seenVersion 剥掉（跟 announced
同一个「旧快照冲掉小本本」的坑）。test-update 第 7 节钉着整条链。

打包（tools/pack.js）第 0 步问「这次改动多大」自动递增 package.json 的
version（bumpVer 在 updates.js，大/中/小 = major/minor/patch，后段归零；
命令行 node tools/pack.js 大|中|小|不动 跳过问答）。号不递增分发就是死的 ——
cmpVer 判不出新旧，朋友那边永远「已是最新」。

几条不许退的（tools/test-update.js 50+ 条守着）：

- **文件名许可名单 `ART_RE` 就是防穿越的全部**。服务端按名发文件前必须过
  parseArtifact；正则不含 / \\ 点点，收包侧 fetchLatest 也用它验 manifest
  里的 file（下载落盘路径由它拼，放宽 = 让恶意 manifest 往任意路径写文件）。
- 版本比较按 . 分段数值比（0.10 > 0.9），别退回字符串比。
- 协议从第一天就按「以后搬上真服务器」设计：latest.json + 包原样上传、
  改个 source 就迁移，代码不动。局域网内无身份验证是**文档里认了的边界**，
  公网必须先加签名校验。

## 「她的大小」与拖动：窗口尺寸只有 petWinSize 一个源头

她是适配窗口渲染的（stage.js 的 layout 按窗口 fit），所以「放大」= 把整个
窗口按比例放大，点击判定/气泡占位全按比例走，渲染层零改动。两条铁律：

- **拖动绝不许 setPosition、绝不许现读窗口尺寸**（test-wiring 第 6 节钉着）。
  显示缩放非 100% 的机器上，每次 DIP↔物理像素换算都四舍五入，现读现写就是
  「拖着拖着变大」（2026-08-22 发出去的机器上实测撞过）。拖动只写
  setBounds + petWinSize 常量。
- **缩放（look.scale，0.6~1.6）只改 petWinSize 这一个源头**，建窗按存档出生、
  预览/保存时 applyPetScale 一次性改。改的时候脚底锚住（往上往两边长）。

## 面板皮肤：全走 CSS 变量

四套皮肤（深空 / 机甲 / 软萌 / 简约）= panel.html 里四组 CSS 变量，
选择器是 body 上的 `data-theme`。规矩只有一条：**正文样式里不许写死颜色**，
颜色、圆角、渐变全用变量 —— 写死一处，那一处就在所有皮肤里长一个样
（软萌和简约是亮底皮，写死的暗色文字在那儿直接看不见）。

存档在 `config.panel.theme`，面板切换时用 `saveSettings({panel:{theme}})`
增量写入。**设置窗口保存时要把 `panel` 键摘掉再交**（settings.js）——
它交的是打开窗口那一刻的整份快照，不摘的话你开着设置窗口期间换的皮肤
会在点保存时被冲回去。dispatch.model 同一个雷，同一处修的。

## 面板的多屏定位

`panelSpot()`：拿角色窗口中心问 `screen.getDisplayNearestPoint` 她在哪块屏，
在**那块屏的 workArea** 里贴着她摆。原来拿的是主屏尺寸 —— 她站在副屏上时，
面板会被主屏的宽度夹回去，出现在离她十万八千里的地方。已存在的面板再次唤起时，
只有「她换了屏幕」才搬过去（你手动摆的位置得尊重），并且每次都 `moveTop()` ——
「找不到任务弹窗」多半是被全屏应用或别的置顶窗口压住了。

画面变化全在 0.5%~1.4%，参数已在极限 —— 厚刘海盖眉毛、小嘴画风，脸零件

## 她会盯着你开出去的终端

点「开终端我看着」开出来的窗口，她**不是开完就不管了**。那边每干完一段，
她会主动过来跟你说一声 —— 气泡上写、嘴里念，你不用一直盯着那个窗口。

汇报里有三样东西：这一轮你让她干的是什么、她最后说了什么、这轮动了哪几个文件。
她卡在权限确认上走不下去时也会喊你一声，不然那玩意能干等一整晚。

怎么做到的：终端里跑的不是裸 `claude`，而是 `hooks/term-shell.js` 包了一层，
它给 claude 注入一个 `WAIFU_TERM_ID`。Claude Code 的 hook 是 claude 的子进程，
能读到这个变量，于是每条 hook 事件都认得出自己是哪个终端发的 ——
这样才能把「她的活」和「你自己另开的窗口」分得清清楚楚。

> **踩过的坑：别想着去读 transcript 文件。**
> 一开始的思路是 Stop hook 给了 `transcript_path`，读文件尾巴就能拿到她说的话。
> 实测完全行不通：**交互式会话的 transcript 要等整个会话结束才落盘**，
> Stop 的时候文件压根不存在，等四十秒也等不来。
>
> 中间还退而求其次试过「读那个目录里最近改过的 jsonl」—— 后果更难看：
> 那个目录里躺着你自己正在用的会话，文件时时刻刻在被写，
> 于是她张嘴汇报的是**别人说的话**，测试还四项全绿。
>
> 正确答案很朴素：**Stop 事件本身就带 `last_assistant_message`**，
> 她刚说完的话现成地躺在 payload 里。绕一大圈回到原点。

不想要这个：`config.json` 里 `"supervise": { "enabled": false }`。
只想要文字不想听见声：`"speak": false`。

## 私聊，还能定制她的性格

「派活」是让她干活，「私聊」就是纯聊天 —— 单独一个窗口，跟任何项目都不沾边。

点右上角「性格」能改她是个什么人。内置几个模板（温柔体贴 / 毒舌吐槽 / 元气满满 /
高冷话少），也可以自己写。改完点保存，**下一段对话**才换性子 ——
聊到一半突然变个人太惊悚了，想立刻生效就点「重开」。

这条会话有三个刻意的设定：

- **她手上一个工具都没有**（`--tools ""`）。闲聊时她动不了你的代码，
  这比在提示词里写「请不要修改文件」硬得多。
- **她此刻的心情会写进人设**。她烦躁的时候说出来的话就是不一样 ——
  不接这根线的话，心情系统就只是换张脸而已，人没变。
- **不加载任何设置源**（`--setting-sources ""`）。省下一大坨系统提示词，
  实测一轮从 $0.014 降到 $0.002；顺带 hook 也不加载，
  所以她自己聊天不会触发 hook 打回自己身上，把心情系统带着跑。

> **踩过的坑：`--append-system-prompt` 压不住她。**
> 用它追加人设，问她叫什么，她照答「我是 Claude，Anthropic 的 AI 助手」——
> 追加的那点东西被 Claude Code 自带的那套庞大身份设定盖得死死的。
> 必须用 `--system-prompt` **整个替换**掉，她才真的变成小依。

## 点她一下，她自己开口

不用打字，**在她身上点一下**（摸头也算），她就主动搭话了 —— 而且那句话是现想的，
不是台词库里那几句轮着念。她知道：

- 现在几点（深夜会催你睡，不会拉你蹦迪）
- 自己什么心情、累不累
- 你多久没理她了，以及**你人还在不在电脑前**（这两件事不一样：出门了 vs 在旁边晾着她）
- **手头开着几个终端、有几个后台任务在跑**
- **你手上有哪些项目、哪个多久没动了** —— 所以她会说「WaifuCode 那边先放放吧，
  吃饭去？」而不是干巴巴的「下午茶时间到了」
- 你 `music/` 里有哪些歌、**每首多快**（她提议跳舞时不用再瞎猜 BPM）
- **你们最近聊了什么** —— 见下面那条

> **她记得上次说了什么。** 每次戳她都是一个**全新的 claude 进程**：它不知道十分钟前
> 你们说过什么，所以她永远在初次见面，说不出「刚才那事你弄完了吗」这种话 ——
> 而恰恰是这种话才像认识的人。
>
> 现在带三样进去：最近 3 次她说过的话、**每句是多久以前说的**（「刚才」得知道是多久）、
> 当时你是戳她还是摸她头。另外**私聊窗口半小时内聊过的也端过来** ——
> 不然你在聊天框跟她聊完、回头戳一下桌面上的她，她会一脸茫然地重新自我介绍，
> 像是两个人。几百个 token 的事，成本上几乎白送。

> **项目列表必须过滤，不然她会说傻话。** `registry.json` 记的是「派过活的目录」，
> 不是「项目列表」—— 这台机器上它躺着 `Desktop`、`music`（音乐文件夹）、
> `.testproj`（测试残留）。不筛的话她会一本正经地说「music 你三天没碰了，
> 要不要接着弄」。判据是「目录里有 `.git` 或 `package.json`」，顺带也挡掉了
> 盘符没挂、目录被删的情况。而且**只报项目名不报路径** —— 路径里带你的用户名。

> **踩过的坑：写「不想提就填 none」是按不住她的。**
> SCHEMA 里那句话一直在，实测 **39 次搭话提了 39 个 offer，`none` 一次都没用过**。
> 模型学会一个新玩具之后总要用一下，不专门按住就永远按不住（跟跳舞那节
> 「平时聊天绝对不许乱动」是同一个毛病）。
>
> 现在两手一起来：description 里把「默认就该是 none」写成强指令；
> 同时**把「你最近连着提了几次」这个事实摆给她看** —— 她每次都是全新进程，
> 不知道自己上一次干了什么，自然每次都觉得「这次提一下挺好」。
> 连着提两次，第三次就硬性要求闭嘴。实测连戳四次：提议 1 次、安静 3 次。

说完她可能顺手提议点什么，气泡下面会冒出两个按钮：

```
哟，还记得我啊？我这边活儿早干完了，一个人在角落里看了好几个小时的屏保。
                                              [ 讲个听听 ]  [ 算了 ]
```

点左边就直接做了。**笑话在提议的时候就一起写好了**，所以点下去是立刻讲，
不用再花一次钱。

用的是 CLI 的 `--json-schema`，逼她吐出严格结构（说什么、什么表情、提议什么、
按钮上写几个字）。让她在回复里夹自定义标记也能做，但按钮上要显示什么、
点了要执行什么全靠这个结构，散文格式扛不住。

> **气泡是穿透的，只有那两个按钮不穿透。**
> 整个角色窗口是块透明画布，不穿透就会挡住你桌面上的图标。
> 所以穿透判定里单独把按钮那一小块框出来 —— 鼠标移到按钮上才收事件。

**成本跟着你的点击走**：不点就不花钱，一次一两分钱。连着戳有 25 秒冷却，
冷却期内退回台词库那几句，她照样有反应，只是不那么应景。
生成要一两秒，这中间气泡上会先摆三个点，不会让你以为点了没反应。

## 跳舞和唱歌

在她身上点右键 → **跳个舞** / **唱首歌**。

### 也可以直接在私聊里点她

不用去翻菜单，在聊天窗口跟她说就行 —— **她会自己编舞**：

| 你说 | 她真的会 |
|---|---|
| 跳个慢一点、温柔一点的 | 76 BPM、幅度 0.5，`sway → wave → shy → sway → pose` |
| 太温吞了，来个嗨的 | 142 BPM、幅度 1.4，`bounce → swing → spin → clap → pose` |
| 随便哼两句，编个关于加班的 | 现编几句词，用她的声音哼出来，同时跟着跳 |
| 唱那首 XXX | 去你 `music/` 里模糊匹配，找到就放；没有就老实说没有 |
| 做个害羞的表情 | 摆六秒，然后回到心情本来该有的脸 |

原理是她回复时可以在**最后一行**附一条动作指令，主进程解析出来执行，
显示给你的话里会把这行剥掉。

```
好呀，那我轻轻跳一支～你坐好看着哦。
<<ACT:{"act":"dance","bpm":76,"steps":["sway","wave","shy","pose"],"amp":0.5}>>
```

为什么不另开一次调用去「解析你想让她干嘛」：那样每句话成本翻倍，
而且会出现「嘴上答应了、身体没动」的割裂。一次调用把话和动作一起定下来，
她说「那我跳个慢的」和她真的跳慢的，是同一个决定。

> 有条底线写进提示词里了：**平时聊天绝对不许乱动。**
> 模型学会新玩具之后总想用一下，不专门按住，你说句「今天天气不错」她都要跳一段。
> `npm run test:actions` 里专门有一条在盯这个。

### 关于「唱歌」能到什么程度

说清楚边界：**她没法凭空唱出一首现成的流行歌**。一是我不会去生成受版权保护的
歌词，二是 Edge TTS 本来就是朗读引擎、不会唱歌（真正的歌声合成要上 DiffSinger
那类本地模型，是另一个量级的工程）。

能做到的是这三种，日常够用：

- **点播你自己有的歌** —— 说歌名，她去 `music/` 里找出来放，跟着跳
- **即兴哼唱** —— 她自己现编几句原创的词，用她的声音哼出来（音调拉高、语速放慢，
  听着像在哼而不是念稿）
- **找不到就说找不到** —— 顺便报几首你现有的，不装作会唱

### 舞是算出来的，不是循环播动作

没走「把模型自带的 motion 一个接一个放」那条路 —— 那些动作本来就是给待机用的，
连着放出来只是「她在动」，不是「她在跳舞」。

这里直接按拍子驱动身体参数：腰左右摆、头跟着歪、肩膀在重拍上弹、腿踏步、手臂甩。
五套舞步（摇摆 / 弹跳 / 手臂波浪 / 踏步转身 / 甩头），每八拍换一套。

顺带白捡 **Live2D 的物理**：身体一动，头发、呆毛、裙子、缎带自己就跟着甩，
一行代码不用写。这是它看起来「像真的在跳」的一大半原因。

> **踩过的坑（而且踩了很久）：这个「白捡」以前根本没捡到，甚至是反的。**
>
> 一帧里库的实际顺序是：
> `动作 → afterMotionUpdate → saveParameters → 表情 → 眨眼 → 视线 → 呼吸
> → physics.evaluate → pose → beforeModelUpdate → update → loadParameters`
>
> 编舞的钩子挂在 `beforeModelUpdate` 上，那是**物理下游** —— 物理这一帧早算完了，
> 读不到你写的值。实测同一段 ±25° 的 AngleZ 跑三秒：挂 `beforeModelUpdate`，
> `ParamSkirt` 摆幅 **0.362**（静止基线 0.379，等于毫无反应）；挂
> `afterMotionUpdate`，摆幅 **2.000**，直接打满。
>
> 更难受的是开跳时会 `stopAllMotions()`，把唯一在驱动物理的待机动作也停了 ——
> 于是**她跳舞的时候头发比站着还死**。
>
> 现在拆成两个钩子：物理输入那几个参数（AngleX/AngleZ/BodyAngleX/Y/Z，
> 解模型自己的 physics3.json 得到）走 `afterMotionUpdate`，其余的还走
> `beforeModelUpdate`（那儿才压得住动作数据）。`npm run test:physics` 盯着这条，
> 量的不是「参数写进去没有」而是**物理的输出**摆了多大 —— 当前模型上是 0.004 → 0.724。

> **顺带修掉的：开合量的行程差了一个数量级。**
> 舞步曲线里 `armL` 一律按 0~1 写（「开到几成」），但模型上 `ParamArmLA` 的实际
> 范围是 **-10~10**（Mao 的 `ParamArmLA01` 更是 -10~30）。原样写进去只走了 8% 行程，
> **现有那几套舞步里的「手臂甩」从来没甩起来过**。现在按模型自报的范围换算，
> 并夹一个上限 8（不对称范围按 60% 算会得出 ×18，那个幅度不是跳舞是求救）。

### 为什么看着不「一顿一顿」

按拍子算出参数只是第一步。直接把算出来的值每帧写进去，动作会明显发顿 ——
「切片感」的本质就是**相邻两帧之间参数跳了一大截**。四个地方会跳，得逐个堵：

| 跳在哪 | 怎么堵 |
|---|---|
| 换舞步是瞬间切换 | 新旧两套一起算，一拍之内交叉淡化过去 |
| 上一套驱动的部位，下一套不管了 | 舞步没写到的参数一律按**中性姿势**参与混合，是「平滑地回到中性」而不是「突然没人管」 |
| 起跳满幅度、停跳当场定住 | 整体强度从 0 渐入、渐出回 0，收干净了才把身体交还给待机动作 |
| 重拍那一下按帧衰减 | 改成按时间衰减，掉帧时节奏感才不变 |

最后所有参数再统一过一道低通（半衰期 55ms），把残余的台阶磨平。

`npm run test:smooth` 会假装自己是渲染循环，逐帧量出跳变有多大：

```
要是说换就换，最狠的一下是 swing→pose 的 angleZ：8.0° 瞬间跳完
实际跑下来最大单帧跳变: 1.48°
平稳跳一分钟（3600 帧）最大单帧跳变: 1.31°
收势后残余幅度: 0.06°
60fps 与 30fps 的轨迹差异: 2.46°
```

> **平滑系数不能写成「每帧乘个 0.15」。** 那个比例是按帧算的，
> 60fps 和 30fps 下的实际速度差一倍 —— 掉帧的时候她的动作会忽快忽慢。
> 得按时间算：`1 - 0.5^(dt/半衰期)`。

编舞守两条纪律：

- **只碰身体，不碰眼睛和嘴。** 眼睛留给自动眨眼，嘴留给唱歌的口型同步，
  抢过来就变成一张僵脸在扭。
- 写参数挂在 `beforeModelUpdate` 上，跟口型同步同一个时机 —— 这个位置是
  「动作和物理都算完、`coreModel.update()` 提交之前」，早一点会被动作盖掉，
  晚一点这一帧不生效。

**她累了会拒绝。** 精力低于 15 就摆手说改天，深夜还会换一句更困的说法。
跳一段掉 4 点精力、涨 8 点心情 —— 一个跳一整天都不累的桌宠，看着就假。

### 唱歌放的是你自己的歌

**这里不预置任何音乐。** 把你自己的音频文件丢进 `music/` 文件夹就行，
支持 mp3 / m4a / wav / ogg / flac。放什么、有没有版权，你自己把握。

> **她不会去音乐平台上抓歌。** 这个项目里没有任何下载、没有任何平台接口，
> 以后也不加 —— 从流媒体平台抓音频是绕过平台授权，「只是自己听」不改变这件事。
>
> 点歌的实际行为是：
>
> | 你说 | 她做什么 |
> |---|---|
> | 具体歌名，`music/` 里有 | 放（歌名 → 歌手 → 文件名，从严到宽地找） |
> | 具体歌名，**没有** | **明确说没有**，报出手上有哪几首，并给一个「帮我搜一下」的按钮 |
> | 「随便来一首」「当前目录随机播放」 | 在 `music/` 里随机挑 |
> | `music/` 是空的 | 直接说空的，让你先丢几首进去 |
>
> 「帮我搜一下」只是拿默认浏览器打开一个普通搜索页，到此为止 ——
> 歌从哪儿来是你自己的决定。
>
> 「随机」的判断放在**按字面找歌之后**：先当它是歌名去找，找不到再看是不是
> 「随便/随机」这类说法。反过来的话，真有一首歌叫《随便》就永远点不着了。

嘴型不是随机张合，是拿音频**实时振幅**驱动的（跟她说话时是同一套），
所以声音大嘴张得大、间奏时嘴闭上。

### 拍子她自己会听

丢进去就行，**不用做任何标注**。放歌的同时她会在后台把中间三十秒解出来、
低通滤掉人声只留鼓点、统计鼓点间隔，几百毫秒就知道这首歌多快，
然后无缝切过去（切的时候会保持拍号连续，不会突然抽一下）。听过一次就记住了。

拍子的来源按可信度排：

| 来源 | 怎么来的 |
|---|---|
| 文件名 `某首歌 [128].mp3` | 你亲自标的，最硬 |
| ID3 的 TBPM 标签 | 很多音乐软件会写 |
| 她自己听出来的 | 上面都没有时现听，结果存进 `sessions/song-meta.json` |
| 118 | 都没有，也没听准（比如纯钢琴曲本来就没鼓点） |

> **踩过的坑：统计鼓点间隔时必须除以跨过的拍数。**
> 不除的话，隔 2 个、4 个、8 个鼓点的间隔会各自折叠到同一个「半速」值上，
> 票数直接压过只有相邻间隔支持的真实拍速 —— 140 BPM 的曲子测出来是 70，
> 她就变成两拍才摆一下。修完之后 80/90/100/120/128/140/160 全都测得准，
> 低速段把握 100%。

### 点歌认标签，不只是文件名

`track03_final(1).mp3` 这种文件名也能点到 —— 她会读 mp3 的 ID3 标签
（v2.3/v2.4 和 v1 都认），拿里面的歌名、歌手、专辑。所以：

- 「唱那首晚风」→ 按歌名找
- 「放首某某某的歌」→ **按歌手找**，同一个歌手有好几首会随机挑一首
- 都没匹配上 → 老实说没有，顺便报几首现有的（带歌手名）

ID3 解析是自己写的，没引依赖 —— 只认四五个帧，犯不上为这点事多一个包。
FLAC 和 M4A 的标签没做，那两种回落到文件名。

### 跟着段落走

一首歌从头摇到尾，看两分钟就腻了。真人跳舞是前奏轻轻晃、副歌整个人放开、
间奏收回来喘口气。

她靠音量包络判断现在是哪一段：拿当前音量比整首歌的响度基准（十几秒时间常数的
滑动平均），明显高就是副歌、明显低就是间奏。三个舞步池按段落切换，
幅度也跟着浮动（副歌放到 1.35 倍、间奏收到 0.55 倍，平滑过渡不会跳）。

**但她自己点名要跳哪几套的时候就不乱换了** —— 你说「跳个温柔的」她编了
`shy → wave`，那就照跳，只有幅度还跟着音乐走。

想先看看效果，跑 `npm run demo-song` —— 用她自己的声音生成一段「啦啦啦」
丢进 `music/`，纯占位的哼唱，看腻了直接删掉那个文件。

> **顺带修掉的坑：嘴巴那个参数不能写死。**
> Hiyori 的口型参数叫 `ParamMouthOpenY`，Mao 的叫 `ParamA`。
> 之前代码里写死了前者，换上 Mao 之后她会**全程闭着嘴**说话唱歌，
> 而且一句报错都没有。现在改成从 model3.json 的 `Groups` 里那组
> 名叫 `LipSync` 的定义去读，模型说什么就是什么。

> **踩过的坑：别把音乐文件的路径直接丢给 `<audio>`。**
> `file://` 会被 Chromium 当跨源资源，`AnalyserNode` 读出来全是 0 ——
> 声音在响，嘴一动不动。得把文件读成字节再包成 Blob URL，那样才是同源的。

## 一起玩点什么

在她身上右键 → **一起玩点什么**。三个玩法，**全程一分钱不花**（题目、干扰项、
对错反馈全是本地生成的，一次 claude 都不调）。

| 玩法 | 怎么玩 |
|---|---|
| **猜猜我在想什么** | 她做一个表情 + 配套的身体动作，你从四个选项里选。三题一局 |
| **猜这是哪首歌** | 从你 `music/` 里随机挑一首，**从中间**放八秒，四选一。歌不够四首就不显示这项 |
| **陪我专注 25 分钟** | 番茄钟。开始之后她**闭嘴**——不主动搭话、不提议唱跳、情绪台词也压住，只换表情。最后一分钟提醒一次，到点喊你起来动动 |

跟「跳舞」「唱歌」的区别是有来回：她出题 → 你答 → 她有反应 → 记分 → 下一题。

> **猜歌绝对不能复用 `perform:song`。** 那条路上 `stage.js` 有一句
> `if (e.title) say('♪ ' + e.title)` —— 一放就把答案念出来了。所以单开了
> `perform:clip`，只带音频不带标题。
>
> **番茄钟用绝对时间戳，不是数 25 次一分钟的 tick。** 后者在电脑休眠、切用户、
> 系统卡顿时都会漂，25 分钟能变成 27 分钟 —— 而这东西的全部意义就是准时。
>
> **石头剪刀布做不了。** 模型的 `ParamHandL/R` 是手的**开合量**不是手势造型，
> 摆不出「剪刀」和「布」的区别，只能靠台词说「我出的是石头」，那就没意思了。

## 她的心情是怎么来的

不是随机播表情。每一次情绪变化都有来由：

| 发生了什么 | 她的反应 |
|---|---|
| 接到活 | 干活中，应一声 |
| 连着报错 3 次 | 烦躁（眯眼、张嘴嚷嚷、呆毛耷拉） |
| 一遍就干成 | 得意（闭眼笑、呆毛翘起来） |
| 干砸了 | 低落 |
| 连轴转很久 | 累 |
| 半夜 / 精力见底 | 困 |
| 好几小时没人理 | 闹脾气（鼓脸、把视线撇开） |
| 一遍就干成之后那几分钟 | 得意（挺胸叉腰，四分钟保质期） |
| 摸头 | 脸红 |
| **连着摸头 4 下** | 受用了（好感涨得少了） |
| **连着摸头 8 下** | 烦了（「够了够了！头发都乱了！」，**倒扣好感**） |
| 被拖来拖去 | 吓一跳（「欸欸欸——！」） |

四个数值：**精力、心情、亲密度、连续报错数**。存在 `sessions/mood.json`，
关掉再开不会重置。

> **踩过的坑（而且是这套系统里最大的一个）：以前它只进不出。**
>
> 精力每分钟 +2（每小时 +120），而跳一整支舞才扣 4 —— 歇两分钟就补回来了。
> 亲密度要连着两小时不理她才开始扣、一次 0.4，随便点她一下 +3 就赚回来。
> 实际跑出来的存档长期是 `energy: 100, affection: 100`。
>
> 而 `computeState()` 里困要 `energy < 18`、累要 `< 38`、闹脾气要 `affection <= 25`
> —— **这三个状态一次都没触发过**。玩法说明里写的「累了会拒绝跳舞」「晾久了会闹脾气」
> 全是空头支票，连带九个情绪动作里有三个永远演不到、台词库里三个 bank 一辈子轮不上。
>
> 现在改成真的有收有支：
> - **醒着就在耗精力** —— 闲着 -0.18/分（陪你坐六个钟头开始喊累、九个钟头撑不住），
>   有活在跑 -0.4/分，深夜再乘 1.6。回血**只发生在关机的时候**（当作她睡了一觉，
>   按小时算，关一整晚回满）
> - **亲密度涨得越高越难涨** —— 刚认识时摸一下 +2.5，很熟了之后再摸只有 +0.6
> - **分得清「你不在」和「你在但不理我」** —— 前者她安静等着（掉得极慢），
>   后者才是真的晾着（-0.22/分）。判据是系统空闲时间，三分钟没碰键鼠就当你人不在。
>   这只读一个「键鼠刚才动过吗」，不看你在用什么软件，也不往任何地方发
>
> `npm test` 里有一段是模拟跑十小时，把这条曲线直接打出来：
> ```
> 2h 精力 78 → normal   4h 精力 57 → normal   6h 精力 35 → tired   8h 精力 14 → sleepy
> ```

除了换表情，这几个数值还连续地改着她的**底噪**：精力越低眼皮压得越狠
（不是切一张「困」的脸 —— 累是个程度，不是个表情）；心情不同呼吸的快慢深浅也不同，
烦躁时又快又重，低落时又慢又浅。呼吸这条还白捡一层：`CubismBreath` 写的那几个参数
正好是**物理的输入**，且跑在 physics 之前 —— 改呼吸节奏等于免费让头发也换个节奏。

判定优先级上有个刻意的设计：「被冷落」排在「心情好」前面。
再高兴，晾久了也要先抱怨一句 —— 真人就是这样。

### 表情是自己造的

Hiyori 官方**一个表情文件都没给**，是用 `tools/make-expressions.js` 生成的 12 个
`exp3.json`。想调表情就改那个脚本里的参数表再重跑，会覆盖重写。

> **踩过的坑：别把情绪压在眉毛上。**
> Hiyori 是厚刘海，眉毛几乎全被头发盖住。第一版给「烦躁」堆了 8 个眉毛参数，
> 实测应用成功但屏幕上跟平静脸没区别。真正看得见的是眼睛开合、眼球方向、
> 脸颊（`ParamCheek`）、张嘴幅度、还有呆毛（`ParamHairAhoge`）——
> 呆毛是个特别好用的情绪放大器，翘起/塌下一眼可辨。

参数用 `Add` 混合而不是 `Overwrite`：后者会把自动眨眼和动作里的眼部数据整个盖掉，
人就僵了。

## 语音

用微软 Edge 的在线 TTS，免费、不用账号、不用梯子。默认音色 `zh-CN-XiaoyiNeural`（晓伊）。

嘴型不是随机张合，是拿音频**实时振幅**驱动的 —— 声音大嘴张得大，停顿时嘴闭上。
实现挂在 Live2D 的 `beforeModelUpdate` 钩子上：这个时机在动作和物理都算完、
`coreModel.update()` 提交之前，早于它写参数会被动作盖掉，晚于它写则这一帧不生效。

只念她自己的情绪台词，不念干活时的输出（又长又密，全念出来会很吵）。
念之前会先洗一遍文本，把代码块、文件路径、URL、markdown 符号都替换掉，
否则会念出一长串「反斜杠 D 冒号」。

> **踩过的坑：一个 TTS 连接同一时刻只能合成一句。**
> 四句话几乎同时触发时，共用那一个 WebSocket，结果是**一起**卡死到超时 ——
> 日志里四条「合成超时」整整齐齐排在一起。而且连接坏了之后从没被丢弃过，
> 于是她从那一刻起彻底哑了，除非重启。
>
> 现在合成走一条串行队列，出错就把连接丢掉重连，闲置超过三分钟主动重建
> （微软那边会静悄悄掐掉没流量的连接）。任务播报还带 `important` 标记，
> 不会被后面的话顶掉 —— 情绪台词丢一句无所谓，「XX 项目干完了」你是真的要听到。

换音色/语速改 `config.json`：

```json
"voice": { "enabled": true, "voiceName": "zh-CN-XiaoyiNeural", "rate": "+8%", "pitch": "+12Hz" }
```

## 她的动作和换装，上限到底在哪（实测，2026-08-06）

写了个参数探针去问模型自己，别再靠猜：

```
npm run probe-params            量顶点：哪个参数掀动了哪些网格、掀多远
npm run probe-params -- --color 量画面：改颜色/改透明度的那批（顶点探针看不见）
npm run probe-params -- --all   连没效果的也列出来
```

**Mao 的实测结果：132 个参数，99 个真的能掀动东西，`dance.js` 只驱动了 14 个。**

### 动作：远远没做到头

按「能掀动多少」排，还没接的大件：

| 参数 | 位移 | 能做出什么 |
|---|---|---|
| `ParamAllRotate` / `AllX` / `AllY` | 20.6% / 6.4% | **整个人的旋转和平移**（178 片网格）—— 跳起来、歪倒、转圈、闪避 |
| `ParamArmRA02` `ArmRB01/02/03` `ArmLA02` `ArmLB01/02/03` | 最高 48.4% | **手臂是分三节的**。现在每条胳膊只驱动了第一节，等于整条摆；接上二三节才有肘和腕 |
| Rabbit / Heart / Aura / Explosion / Smoke / Ink / Wand / HealLight | 最高 104% | Mao 是魔法师，**自带一整套演出特效**，一个都没用过 |
| `ParamA/I/U/E/O` | — | 五个元音，**真口型同步**（现在是拿音量驱动张嘴） |
| 8 个 `ParamBrow*` | — | 眉毛。表情信息量最大的部件之一，完全没碰 |

顺带查出来的：**Mao 没有 `ParamLeg`**，所以 `step`/`bounce` 那两套舞步里的踏腿在她身上是空转的。

### 已经接上的（2026-08-06 下午）

**手臂分节** —— `armL2/armL3/armR2/armR3` 接到 `ParamArmLA02/03`、`ParamArmRA02/03`。
只接 A 那条链，**不碰 ArmLB/ArmRB**（那是同一条胳膊的另一个姿势，归 pose3 管，
两条一起写会打架）。`wave` 的波浪现在是肩→肘→腕各差四分之一拍传下去的，
`clap` 的手能真的合到一块。

**整个人** —— `allX/allY/allRot` 接到 `ParamAllX/AllY/AllRotate`，列进 `ANGLE_KEYS`
（单位就是参数自己的 -10~10，不做行程换算）。`bounce` 现在真的离地，
`spin`/`step` 带整体旋转和平移，姿态层里「累」是整个人下沉、「闹脾气」是侧开半步。

> **符号方向是量出来的，不是猜的。** 实测模型空间里头在 y=0.354、腿在 y=-0.394，
> 所以 **+Y 是上**；`ParamAllY` 从 -10 到 +10 时脸从 0.312 挪到 0.396，
> 所以 **+allY = 往上**；`ParamAllRotate` 正值把脸推向 +X，即**往右倒**。
> 猜错的代价是「高兴的时候往下沉」，看着就是坏的。

> **「换配色」做过又删了 —— 记在这儿免得再犯。**
>
> `ParamAllColor1/2` 被我当成了整体配色开关，依据是探针量出「画面变了 9.7%」。
> 上线之后用户问「这配色有啥用」，我才**第一次真的去看四套长什么样** ——
> 四张截图**一模一样**，唯一区别是脚底下多/少一团微光。那 9.7% 是那团低对比度
> 光晕铺开的面积，根本不是衣服变色。
>
> 两条教训，都不新鲜但我都犯了：
>
> **① 像素差分只能告诉你「变了」，不能告诉你「变成什么」。**
> 判断一个视觉功能有没有用，最后必须真的看一眼图。探针给的是证据，不是结论。
>
> **② 存配置前先查这个键有没有主。** 我把选择存进 `look.tint`，
> 而那个键**本来是设置面板「色调」用的**（none/warm/cool/night/…），
> 等于悄悄把用户的色调设置覆盖成了一个无效值。
>
> Mao 真正能换色的路是下面那条「换贴图」，已经验证可用。

npm run probe-uv                      每个部件真正占了贴图上多少像素
npm run probe-uv -- --verify=PartHat  把它涂成品红贴回去，验证掩膜对不对

```

三件事实测过：

1. **运行时换贴图有效** —— `model.textures[0] = PIXI.Texture.from(canvas)` 换成纯品红，
   画面变了 11.78%。库版本没挡这条。
2. **掩膜是对的** —— 把某个部件涂成品红贴回去，屏幕上只有那一小块变了（噪声底 0）。
3. **抠出来的是完整图集尺寸的图**，只有那个部件的像素、其余透明，改完能原位贴回。

> **踩过的坑一：不能用「部件的包围盒」去裁。**
> 头一版就是这么写的，跑出来 115 对部件互相重叠 —— 因为**一个部件的网格是散落在
> 图集各处的**（打包器按零件塞，同一部件的零件根本不挨着）。PartHoodie 16 片网格
> 的包围盒占了整张图的 38%，裁出来会带走一大堆别人的东西，贴回去就把别的部件盖了，
> **而且不会报错**。改成按三角形逐个画掩膜之后，同一个部件实际只占 6.83%。
>
> **踩过的坑二：验证时必须先把参数冻住。**
> 前后两张截图的差异绝大部分是她在呼吸眨眼 —— 不冻的话噪声底 3%，而贴图替换本身
> 才 1%，直接被淹掉，还会给出「变化遍布全身」的假象（PartHat 和 PartFace 量出来
> 是同一片区域，一看就不对）。
>
> **踩过的坑三：`capturePage()` 的位图尺寸不等于窗口尺寸**（按设备像素比出图）。
> 把宽度写死成窗口宽的话，算出来的 x/y 全是错的，而且看着还挺像那么回事。

**能换的是颜色、花纹、材质；换不了版型** —— 版型由网格几何决定，跟贴图无关。
交给画图的（人或者模型）时，三条规矩：尺寸不许变、位置不许挪、透明处保持透明。

### 真跑通了一次（AI 画花纹 → 穿上身）

```
codex exec "…生成一张 1024x1024 无缝可平铺的魔法布料花纹…"   # gpt-image-2
npm run probe-uv -- --model=models/Mao/Mao.model3.json --cut=PartRobe \
  --pattern=花纹-AI.png --out=models/Mao/skins/翡翠长袍.png --shot=效果.png
```

结果：长袍从深藏蓝变成翡翠绿，**褶皱、阴影、缝线一根没少**，
帽子/帽衫/腿/鞋一个像素没动。成品留在 `models/Mao/skins/翡翠长袍.png`，
右键 →「换套贴图」就能穿。

> **分工必须反过来才行：模型只画花纹，像素级的活交给程序。**
>
> 一开始的想法是「把抠出来的图交给 AI 改」。行不通，三条硬伤：
> 图像模型**没法保住像素级排布**（它会重新理解并重画整张图，贴回去褶皱缝线全错位）；
> gpt-image-2 **不支持透明背景**；尺寸只有 1024 档，跟 2048 的图集对不上。
>
> 改成让它画一张**无缝平铺的花纹**，程序用 `color` 混合铺上去 ——
> 色相饱和度取自花纹、**明暗取自原图**，于是所有褶皱阴影都留着。
> AI 干它擅长的，对齐这件事一秒都不用它操心。
>
> 副作用：`color` 混合保明暗，所以**只能改色相和饱和度、改不了明暗**。
> 深色衣服贴一张深色花纹几乎看不出变化（我第一次拿深蓝星空贴深蓝袍子就是这样），
> 要效果明显得挑**色相反差大**的。

`models/<模型>/skins/` 底下的东西会自动出现在右键菜单「换套贴图」里。两种形态：

| 放什么 | 换什么 |
|---|---|
| `skins/名字.png` | 只换第 0 张贴图（上面那套花纹工具产出的就是这个） |
| `skins/名字/texture_NN.png` | **整套换**：按号对位，目录里没有的那号保持原装 |

目录那条是给**换皮模型**用的（`src/main.js` 的 `atlasUrls` 把它摊平成一串 url）。
一身配色往往要动好几张图 —— 海梦九张里有六张不一样。只换第 0 张的话，
**头发变了衣服没变**，是个半拉子状态，而且不报错。

`setAtlas` 收三种东西：假值（全部换回原装）、一个路径（老写法，只换第 0 张）、
一个数组（按下标对位，`null` 那格保持原装）。数组里**只要有一张不属于当前模型就整套拒掉** ——
半套皮肤比不换更难看。摊平和转 url 都在主进程做完：渲染层是个 `file://` 页面，
读不了目录，也认不了 `D:\` 开头的路径。

> **贴图存档必须按模型分开存。** 头一版存成全局一个字符串 —— 给 Mao 选了皮肤、
> 转头切到 Hiyori，启动时照样把 Mao 那张 2048 的图糊上去，每片网格取到完全不相干
> 的像素，出来是一张糊脸（眼睛长在下巴上、衣服上印着别人的鞋），**一句报错都没有**。
>
> 现在两道锁：存档按模型路径分键（老的全局字符串读的时候挡掉、写的时候自动升级成对象），
> 渲染层 `setAtlas` 再查一遍这张图在不在当前模型目录里。
> 后一道是关键 —— 存档是可以被手改的，也可能是旧版本留下的，渲染层不能信它。
启动时记的是原装那**几**张贴图（`baseTextures`）—— 存底必须在 boot 时做，
等 `setAtlas` 第一次被调用才存的话，「换回原样」拿到的是换过之后的那张。

> **开机穿不上，查了才发现是个类型错。** 渲染层原来这么写：
> `if (cfg.look.atlas) setAtlas(cfg.look.atlas)` —— 可 `look.atlas` 是上面那张
> **按模型分键的表**，不是一个路径。`String({...})` 出来 `"[object Object]"`，
> 归属判断当场判否 → **每次开机都退回原装**，你上次选的皮肤白选，一句提示都没有。
>
> 现在主进程在 `pet:get-config` 里就把它摊平成 `cfg.atlas`（一串 url），
> 渲染层不再自己去翻那张表。`tools/mock-preload.js` 也跟着给了这个字段 ——
> 替身要是继续糊过去，自检就永远看不见这个坑（test-stage 第 13 节现在有一条
> 「开机就穿着存档里那套」守它）。

> 只放开被测那一个，噪声底就降到 **0.00%**。只冻被测参数不够 ——

### 表情：**必须量，不能靠名字猜**

`npx electron tools/expression-sheet.js --model=…` 把一个模型的所有表情排成一张
联络表，每张脸下面标一个 Δ（跟「不加表情」比，画面差了百分之几）。
**Δ 0.0% 就是这张表情屏幕上什么都没发生。**

这个工具是被海梦逼出来的。她自带七个表情叫 `expression1`~`7`，
参数叫 `Param40`、`Action03` —— 照名字猜，配进 faceMap，结果她的脸
**从头到尾一动不动，日志里一个字都没有**（切表情失败是静默的）。
量完才知道：七张全是 0.0%，其中四张改的 `Param40/Param43` 其实是
「hands on hips」——**叉腰，是个身体动作**。

做这张表有四个坑，每个都能让它给出完全错误的结论：

| 坑 | 表现 |
|---|---|
| 用「每帧把参数写回快照」冻画面 | 那个钩子（`beforeModelUpdate`）跑在表情**之后**，每张脸都被抹回中性 → 一排一模一样的脸 |
| 忘了鼠标静止 8 秒她会**走神** | 前三张老实、后面整齐地差 21.9% → 看着像「后几个表情效果一样」 |
| 忘了开场那句「我在的」气泡 3.2 秒后消失 | 差异像素全落在气泡上 → Δ 全变成同一个数，连「脸在哪儿」都算歪 |
| 拿外接框中心当脸的位置 | Rice 是横版画布、人站右边 → 裁出来是一条肩膀，十二张脸全 0.0% |

现在的做法：掐掉待机动作 / 眨眼 / 呼吸 / 物理 / 视线 / 自然摆动、藏掉气泡，
**脸的位置靠差分自己找**（把所有表情跟中性的差异像素并起来，那块就是脸），
最后再拍一张中性的跟开头对比 —— 差得多就说明这一趟里有东西没清干净，
上面每个 Δ 都不可信，工具会自己喊出来。

> **换皮的别当新角色收。** 同一个 moc3 换一身贴图，是**一个角色的两身衣服**。
> 当成两份模型目录收进来的话：设置里冒出两个同名同脸的人（海梦一度占三个名额），
> 每份还把十几 MB 的 moc3 和动作重复存一遍，而且每加一身都得再抄一份档案。
> 正确的放法是 `models/<本体>/skins/<这身叫什么>/texture_NN.png`。
>
> `tools/test-profiles.js` 第 7 节守这个：**两个目录共用同一个 moc3 就报红**，
> 顺手也查皮肤目录里的贴图号对不对得上。它一上来就抓出了 Tororo = Hijiki ——
> 这两只猫我自己都没意识到是同一个模型。四份折进去之后 `models/` 从 ~96M 降到 84M
> （搬走的是重复的 moc3、动作、表情；跟原装一模一样的贴图也没搬）。

### 踩过的三个坑

**① Ren 打不开，是 Core 版本的事，不是模型坏了。**
moc3 有版本号（文件第 5 个字节）。Ren 是 Cubism 5.3 导的，moc3 已经到第 6 版，
而原来 `vendor/` 里那份 Core 是 5.1.0，只认到第 5 版：

```
[CSM] [E]csmReviveMocInPlace is failed. The Core unsupport later than moc3 ver:[5]. This moc3 ver is [6].
```

这行只出现在 renderer 控制台，界面上就是**一片空白**，别的什么提示都没有。

**② 升到 Core 6.0.1 之后，所有模型的渲染一起坏了 —— 而且看不出来。**
Core 6 把每片网格的渲染次序从 `model.drawables.renderOrders` 挪到了
`model.renderOrders`（5.2 之后多了 offscreen，次序表要把 drawable 和 offscreen
排在一起）。pixi-live2d-display 打包的 Framework 还是 Cubism 4 时代的，
还在读旧位置，读到 `undefined`，`doDrawModel` 里 `e[i]` **每帧抛一次 TypeError**。

表现有多迷惑：人还在、还会动、还会说话，`test-stage` 里却有 5 项莫名其妙地挂
（视线、眼皮、藏部件全失败），日志上只有孤零零一行
`Cannot read properties of undefined (reading '0')`，不给堆栈。

官方 SDK for Web 从 `5-r.4`（Core 5.1.0）直接跳到 `5-r.5`（Core 6.0.1），
**中间没有既认 moc3 v6 又留着 renderOrders 的版本**。所以是在
`vendor/live2dcubismcore.min.js` 末尾贴了段垫片，包一层 `Model.fromMoc`，
给 `drawables` 补一个 `renderOrders` getter。贴在 Core 上而不是贴在那 5 个加载
`cubism4.min.js` 的地方，是为了桌宠本体和 tools/ 下的脚本一个字都不用改。
**以后换 Core 记得把那段带上**，文件末尾有完整注释。

**③ 每个模型都要量「嘴在哪、头到哪儿为止」，别拍脑袋。**
`headRatio`（摸头摸得着的范围）和 `mouthRatio`（气泡从哪儿冒）以前是手调的，
新加十个人不可能一个个调。加了个量尺：

```
npx electron tools/probe-parts.js --face --model=models/Chitose/chitose.model3.json
```

原理是**拧参数看哪片顶点动了**：把 `ParamMouthOpenY` 推到 1，动了的那几片网格就是嘴；
让她 `ParamAngleZ` 转 30°，跟着转的那一大片就是脑袋。网格 id 大多是 `ArtMesh37`
这种流水号，名字里根本没有 mouth，但参数 id 是有语义的。

拿手调过的 Hiyori 校准：量出 `headRatio` 0.36，手调值 0.34 —— 可以信。

> 这里面有两个当场翻车的点：
> ① **分母必须是画布**（`canvasinfo`），不是「可见顶点铺开的范围」。stage.js 那边
> 用的是 `model.getBounds()`，量的就是画布。拿顶点范围当分母，画布留白多的模型
> 会算出一个偏上十几个百分点的嘴，气泡直接飘到额头。
> ② **`canvasinfo` 里的宽高是像素，顶点坐标是模型单位**，差着一个 `PixelsPerUnit`。
> 忘了除的话每个模型都会算出漂亮的 `0.50` —— 分子比分母小三个数量级，
> 结果恒等于原点那一半，而且看着特别像那么回事。
>
> 还有一类量不准的，得自己收：**长发和四条腿**。头发跟着头转，会把「头」的下边界
> 一路拖到腰上（Izumi 量出 0.85）；猫和狗的头跟身子是连着动的（量出 0.65 / 0.71）。
> 这几个是照截图改的，档案里都标了。

它还会报一行「人占画布纵向百分之几」。**超出 0%~100% 的模型别收** ——
构图、气泡、点击判定全是按画布算的，人画到画布外面去，在窗口里就是偏的。
ずんだもん（67%~157%）就是因为这条没要，Rice（横版、人在右边）是历史遗留。

## 情绪动作

心情一变，身体也跟着表个态 —— 光换张脸太单薄：她说「烦死了」的时候头得真的甩两下，
说「不弄了」的时候肩膀得塌下去。

九个动作：开心蹦两下、得意挺胸叉腰、害羞侧身低头、吃惊后仰、烦躁甩头、
累了垂头塌肩、犯困打盹、闹脾气扭头、来劲了往前凑。

跟舞步的区别是**不循环**——给一个 0→1 的进度走完就退场，走完自动收回中性姿势。
正在跳舞时不插队（不然动作会打架）。

设置面板「她」那页的**「情绪动作」开关现在真的管用了** —— 以前 `gesture` 那块配置
压根没传到渲染层，勾不勾都一样。

唱歌时还多一层：**副歌来了脸也跟着变**（`excited`），间奏收回来（`shy`）——
靠的是编舞那边的段落判断，身体和表情是同一个信号驱动的。

## 气泡挂多久：字看得完，语音也念得完

原来是 `say()` 传一个写死的毫秒数，于是两头都不对：

- 一句四十个字的话照样 4 秒就收，**你看到一半它就没了**
- 语音是异步合成的、几秒后才到，到的时候气泡早收了 ——
  常见的样子是「字先没了，然后一个没有气泡的她开始念」

现在三个数取最晚的那个：

| | 管什么 |
|---|---|
| 按字数算的下限 | 中文朗读约 4.5 字/秒，任何情况都不许早于它 |
| 合成中的保底 | 语音还在路上，先把气泡摁住别走 |
| 真实音频时长 | metadata 一到就换成精确值（可以往回缩，但同样不许早于「看得完」） |

`hold=0`（出题时「挂着别自动收」）不受这些下限影响 —— 题目自己消失这局就废了。

## 聊天时她是有表情和肢体的

### 17 种情绪：把「负面和玩闹」那半边补上（2026-08-20）

原来只有 11 种，问题不是数量少，是**缺的那一半恰好是真人最常有的**：
能开心能低落，但不会翻白眼、不会坏笑、不会真的火。补了六种：

| 新情绪 | 脸怎么做 | 身体怎么做 |
|---|---|---|
| `angry` 真火了 | 眼睛**睁着瞪**（frustrated 是眯着的）、眉压到底、呆毛炸 | 往前逼一步、肩膀端起来 |
| `scorn` 鄙夷 | **半垂眼 + 俯视**（不屑的核心）、单边挑眉、嘴角撇 | 抬下巴、整个人侧转开 |
| `playful` 搞怪 | **单眼眨**（左右眼开合不对称，最好读的搞怪信号）+ 咧嘴 | 歪头晃两下、耸肩 |
| `curious` 好奇 | 睁大 + 抬眉 + 视线偏一侧 | 探身凑近（跟 surprised 的往后仰正相反）|
| `panic` 慌了 | 瞪圆 + 眉高 + 嘴大张 | 一抖、缩肩、往后半步 |
| `bored` 无聊 | 半垂眼 + **视线飘开**（跟 tired 的区别就在这儿）| 往下泄一口气、头歪一边 |

几条经验：

- **单眼眨是性价比最高的一张脸**。所有模型都有左右分开的眼睛开合参数，
  左闭右睁一眼就读出来是「坏笑」，比任何眉毛嘴角的组合都醒目。
- **生成派和自带派要分开处理**。6 个 `faceMap: null` 的模型（Hiyori/Mark/Rice/
  猫/汪子/海梦）在 `make-expressions.js` 里补参数重新生成；7 个用自带表情的
  只能**映射到已经量过的脸**上 —— angry 和 scorn 在它们身上共用一张怒脸，
  差别全交给身体（这是有意的，不是偷懒；照名字猜一个没量过的表情名 = 静默失效）。
- **Ren Foster 的 `panic` 故意不给**。她一共五张脸，没有吃惊那类；照她档案里
  一贯的规矩「与其硬套一张不像的，不如让脸留在原样」，surprised 和 panic 都空着。
- 汪子和猫的幅度天生小（脸在画面里就那么点）：新脸量出来 0.4~1.6%，跟它们
  自己的老脸一个量级，那是模型天花板不是没写好。

### 量具自己会撒谎：取景框被「叉腰」撑坏（踩过）

`expression-sheet.js` 的取景框原来取**所有表情变化区域的并集**。海梦的 `proud`
会叉腰（Param40/43 是手臂），那一张的变化区域是整个人 —— 并集当场被撑成全身框，
于是**十八张脸的 Δ 全被稀释成 0.3%，一律标成「几乎没变化」**。照这个结论去改，
会把一批本来好好的表情推倒重做。

修法：先算各张变化区域的面积中位数，**超过中位数 6 倍的不参与取景**（动身体的
那张照样出现在联络表里，只是不决定镜头）。修完海梦的真实数字是 0.6%~4.9%，
她原有那 12 张脸一直是好的。

**教训**：「量出来没变化」也可能是量具的错。改表情之前，先确认联络表裁的是脸。

她**每句话**都会在末尾标一个语气（`<<M:happy>>` 这种，界面上看不到），
桌面上那个她据此换表情、演一个情绪动作、并把姿态挂上十几秒。

跟 `<<ACT:...>>` 不是一回事：ACT 是「她决定去做一件事」（跳个舞、唱首歌），偶尔才有；
这个是每句都有的语气标注。做成一个极短的标记而不是再开一次 API 调用 ——
多这一行的代价是几个 token，单独调一次「分析这句话的情绪」是整整一次请求。

> **踩过的坑：认不出来的情绪名会把整行标记漏进气泡。**
> 正则原来写的是 `<<M:\s*([A-Za-z]+)\s*>>`，只认字母。她偶尔会自己发明一个
> `<<M:狂喜>>`，那个正则**压根匹配不上**，于是整行原样显示在气泡上。
> 现在里面收得很宽（`[^>]*`），先摘掉再拿白名单校验：认不出来就只丢标记、不换表情。

## 干活时她身上一直有状态（不是干完才说）

派出去之后那几分钟原来是**完全没反应**的 —— 你不知道她在正轨上还是在挖坑，
等她开口时可能已经改了二十个文件。

数据本来就全在 `terminals.js` 的记录里（工具数、错误数、动过的文件、多久没动静、
是不是在等你确认），但只喂了两个地方：面板列表，和一段结束时那句汇报。
中间那几分钟没人用。

`_pulse()` 挂在现成的 3 秒 sweep 上，把这些折成四个状态推给渲染层：

| 判据 | 状态 | 她身上 |
|---|---|---|
| status === 'waiting' | waiting | 转过来正对着你、抬头 |
| errorCount >= 3 | struggling | 绷起来、头压低、呼吸变快 |
| running 但 45 秒没事件 | stuck | 歪头停住 |
| 其余 running | working | 微微前倾 |

三条设计上的取舍：

**只在状态变了的时候吐。** 工具数每秒都在涨，跟着吐的话渲染层每三秒被打断一次，
姿态永远在重新淡入，看着像结巴。

**不碰心情系统、不说话。** 说话要花钱，而且每隔几分钟念一句进度比不说还烦。
身体是免费的，也是这个形态独有的 —— 余光就能扫到，IDE 插件做不到。

**好几个终端一起跑时挑最要紧的那个**（waiting > struggling > stuck > working）——
她只有一个身体。

姿态优先级：`tempPosture（摸头 / 在想） > workPosture > moodPosture`。
干活那层排中间是因为它挂得最久，但你伸手摸她的时候那件事显然更即时。

> **门槛都往宽了取。** 她身上的状态是给你余光扫的，宁可慢半拍，
> 也不能一有风吹草动就变脸 —— 那样比不动还乱。

### 活干完的那一下：一段接错了地方的代码

「干完一个活是什么反应」这套东西一直都写着，而且写得挺细 —— `mood.onTaskDone`
里有「一遍过就得意四分钟」「砸了就别端着了」「砸了的不算数（tasksDone 不加）」，
还连着「一起干完第 100 个活」那些日子。

**可它在正常使用里一次都没跑过。** 它只挂在 `sessions.on('done')` 上，而那是
无头模式；默认早就换成真终端了（`dispatch.mode` 不是 `headless` 就走
`openLaneTerminal`）。终端那条路上，活干完只有一个 `emit('change')` ——
列表里那条变灰，她本人一点表示都没有。

这类 bug 最难发现：**没有报错，功能「看起来是有的」**（代码在、注释在、
甚至有测试覆盖 mood 那一层），只是没有人调用。

现在 `terminals.js` 干完时发 `finish`：

| 字段 | 干嘛的 |
|---|---|
| `dispatched` | 她被派出去的活（`minimized`）还是你自己开的终端 —— **反应大小不一样** |
| `ok` | 退出码。拿不到时（SessionEnd 那条路）当成功，**宁可少沮丧一次** |
| `errors` / `turns` / `elapsedMs` | 喂给心情结算 |

上层：派出去的活走完整的 `mood.onTaskDone`（有台词、会说出来、算进「干完几个活」）；
你自己开的终端只 `mood.flash` 一下脸，一个数值都不动 —— 不然你敲一晚上代码，
她的情绪会被你的编译结果带着上蹿下跳（`onPhaseDone` 的注释里早就写了这条线）。

两个坑：

**`close` 和 `SessionEnd` 可能都会来**（前者是 claude 自己退了，后者是 hook 报的）。
不挡住的话心情结算跑两遍：能量扣两次、「干完几个活」多算一个。`rec.finished` 挡第二次。

**光靠结算不保证脸上有变化。** 「成了但中间报过错」只加 10 点心情，多半跨不过
任何一条阈值 → `computeState()` 返回的还是原来那个状态 → 表情一动不动，
你根本看不出活干完了。所以结算之后再 `mood.flash` 一下（3.6 秒，不动任何数值）。

### 临时表情收工后，得回到「干活那张脸」

`work:pulse` **只在状态变了的时候才吐**（见上面那条取舍）。于是任何一次临时表情
——被摸、报错闪一下、到日子了——结束之后，`mood:change` 会把脸设回「心情那张」，
而干活那张脸要一直等到下次状态变化才回得来，中间可能是好几分钟。

修法在渲染层的 `mood:change` 里：手上有活时，"本来该有的脸"是 `WORK_FACE[workPosture]`
而不是 `faceFor(moodState)`。`reason === 'flash'` 是有意要闪的那一下，不拦。

## 「僵硬」的物理量是加速度，不是速度

用户说「有些动作太过僵硬」。这话没法直接改代码，得先把它变成一个能量的数：

**速度大只是动作快**（甩头本来就该快）。真正被肉眼读成「顿了一下 / 机械感」的
是**速度突变**，也就是加速度尖峰。逐帧量九个情绪动作，两处元凶：

**① 包络是直线。** 老写法 `Math.min(1, t * 4) * (t > 0.75 ? (1 - t) * 4 : 1)` ——
0 一下变成满速、满速一下变成 0，两个拐点。换成 `envelope(t, attack, release)`
（两头套 `ease()`）之后，「摆姿势」那五个的加速度峰值 0.13 → 0.065，腰斩。

**② 收尾当场撒手。** `_frameGesture` 演完就 `this.gest = null; return`。
可 `this.cur` 是带 0.055 秒惯性跟过来的，包络归零那一刻它还差一点没到中性——
**那点残余被瞬间抹掉**。逐帧量出来最刺眼的证据：*每个动作的加速度峰值都正好
落在它自己结束的那一刻*（happy 1.80s、proud 2.40s、lonely 2.60s…）。
现在演完之后继续用中性姿势喂几帧，收到 `_nearNeutral()` 才真的撒手：
收尾加速度 0.154 → 0.033（剩下的是「蹦两下」最后落地本身的顿挫，那是该有的）。

`tools/test-smooth.js` 第 7 节守这两条。**这条断言验过会红**：把收尾改回
「当场撒手」，它立刻报 0.154。

### 眼皮也不能一步到位

`look.setDroop()` 原来是直接赋值。心情一变（切到「困」），这个数从 0 跳到 0.72，
**一帧之内走完** —— 眼皮「啪」地砸下来一半，看着像掉帧。现在 `setDroop` 只改目标，
真正的值在每帧的钩子里按 0.5 秒半衰期逼近（按秒算不按帧算，掉帧时不会忽快忽慢）。

> **顺带查出一个真 bug：眼皮的上限和「困」那张表情会叠。**
> 猫的待机动作把 `PARAM_EYE_L_OPEN` 常年按在 0.5（猫本来就半眯着），
> 而生成的「困」脸又 Add 了 -0.9 —— 两边叠起来实测按到 **0，完全闭死**，
> 精力一低她就全程闭眼，看着不是困是睡死了。猫那张表的眼睛开合已经收到
> -0.3，眯的形状交给 `PARAM_EYE_FORM`（模型作者专门给的眼形参数）。

## 常驻姿态：不戳她也看得出她什么状态

情绪动作是「演两秒就收」，姿态是**一直挂着**：她今天没精神，那就一整天肩膀都是塌的。

补的是一个挺尴尬的窟窿：心情从 25 跑到 85，身体动作**一模一样**（9 个 Idle 随机轮播），
所有数值都在肚子里、屏幕上一点都看不出来。眼皮和呼吸那层（`applyBodyTone`）早就有了，
**骨架那层一直没有**。

| 状态 | 身上什么样 |
|---|---|
| 困 / 累 / 低落 | 肩膀塌、头往下坠、呼吸浅 |
| 开心 / 来劲 / 得意 | 重心提起来、肩膀打开 |
| 闹脾气 | 身子和头都侧开，不看你 |
| 正被你摸着 | 眯着眼往你手的方向蹭 |
| 摸太久了 | 躲开半步，头别过去 |
| 正在想话（等她开口那几秒） | 微微仰头偏一边，视线往上飘 |

三方（心情 / 当下在发生的事）会抢同一个身体，所以 `stage.js` 里只留一个出口
（`refreshPosture`），临时的压过心情的。不然就是「谁最后调用谁赢」：
你摸着她的时候心情刚好走了一拍，手还没松姿态就自己弹回去了。

### 为什么这层必须是加法，以及加法的那个坑

待机动作本来就在写这些参数。姿态要是写绝对值，等于把待机动作按死 ——
她会僵在一个姿势上一动不动，**比没有姿态还糟**。所以读一下当前值再加偏移。

坑在于：帧末的 `loadParameters` 还原的快照里**含着我们自己写的偏移**。下一帧开头，

- 待机动作驱动的参数 → 被重新写成绝对值，偏移没了，**该加**
- 动作**没**驱动的参数 → 还带着上一帧的偏移，再加一次就是**双份**

每帧多加一份，几秒钟角度就是几百度，人直接飞出屏幕。而「哪个动作驱动了哪些参数」
是没法在代码里猜的。

判据用的是现成的：**记住上一帧我们写进去的最终值**，这一帧读回来对一下 ——
一模一样说明没人动过它（第二种，得先减掉旧偏移），对不上说明动作重写了（第一种，直接加）。

```
npm run test:posture
```

这个自检**照着真实帧管线复刻了一个假模型**（包括「动作只重写它驱动的那几个参数」
和「loadParameters 会把 beforeModelUpdate 写的还原掉」），跑满 10 秒逐帧盯漂移。
不复刻这两件事，那个事故根本测不出来。

## 你走开一阵子回来，她抬头看你一眼

`powerMonitor` 那个「人在不在电脑前」的信号以前**只喂给心情算数值**，屏幕上没有任何
反馈 —— 你走开一小时回来，她跟没事人一样坐着。

现在抓的是 idle→active 那个**边沿**：走开超过 15 分钟才算数（接杯水回来就一惊一乍
比没反应还烦），超过 90 分钟她会闹点小脾气而不是高兴。

台词从本地台词库挑、动作是本地算的，**一分钱不花**。
探测从 60 秒一拍改成 20 秒 —— 「你回来了」要是能晚一分钟才反应，那就不叫反应了。

## 终端里突然满屏乱码：多半不是桌宠的锅

症状：通过桌宠开的终端，claude 跑着跑着中文全变成 `鈥`/`闀`/`鍥`，
连 ANSI 转义码都漏成文字（`?[3G`、`?[38;2;51;51;51m`），最后连输入框都看不见。

**先别怀疑启动器。** 用字节算一遍就知道是哪种错法：

```
•  ESC [ 3 G      UTF-8 字节:  E2 80 A2 1B 5B 33 47
按 GBK 解码:      E2 80 → 鈥     A2 1B → ?（非法组合，把 ESC 吞了）    5B 33 47 → [3G
屏幕上:           鈥?[3G                    ← 跟截图一模一样
```

所以是 **UTF-8 的字节被按 GBK 解码**，也就是控制台代码页从 65001 变成了 936。
转义码漏出来不是 VT 没开，是 ESC 被吞进了非法字节对 —— 这个细节能帮你排除一大半方向。

**根因通常是：会话里跑过的某个 `.bat` 改了代码页。**
`chcp` 改的是**整个控制台**的属性，不是单个进程的 —— 子进程改了，claude 的输出就跟着废，
而且改回不来（没人还原）。

实际抓到过一次：用户项目里的 `一键打包.bat` 第 2 行是 `@chcp 936 >nul`
（那个 bat 自己是 GBK 存的，它需要 936，本身没错），claude 跑了它之后，
整个窗口就废了。

### 排查方法（两步，都很便宜）

1. **先证明链路是干净的。** 造一个跟 `_writeLauncher` 一字不差的启动器，
   把 `claudeBin` 换成一个只跑 `chcp > 文件` 的探针，用 wt 原样拉起来。
   探针站的正是 claude 的位置，它报 65001 就说明启动器没问题。
   （实测就是 65001 —— 一开始怀疑是 `title` 行里那个 `·` 破坏了 `chcp`，**验下来是错的**。）
2. **再去项目里搜 `chcp`。** `grep -rn "chcp" 那个项目` —— 一般一抓一个准。

### 为什么**不**在心跳里强行把代码页设回 65001

想过：`term-shell.js` 有 5 秒一次的心跳，顺手 `chcp 65001` 就能自愈。
**不能这么干** —— 人家那个 bat 要 936 是因为它自己的输出就是 GBK 的。
你每 5 秒抢回 65001，claude 的界面是好了，**他的打包日志全乱了**。
两边只能有一个对，而这时候该对的是他正在跑的那个东西。

正确的修法在**源头**：那个 bat 用完把代码页还回去。

```bat
@echo off
@for /f "tokens=2 delims=:" %%a in ('chcp') do set "_CP=%%a"
@chcp 936 >nul
call :main
@chcp %_CP% >nul
exit /b %ERRORLEVEL%
:main
    ... 原有内容不动 ...
```

（包成 `:main` 是因为里头有好几个 `exit /b`；`call` 之后那些只退出子过程，
所以还原那句一定跑得到。）

### 当场救急

那个窗口里 claude 还开着、界面已经看不清了：`/exit` 盲敲退出 →
`chcp 65001` → `claude -c` 接着上次聊。或者干脆关掉窗口重开。

## 存档/配置的 BOM 陷阱

`config.json` 和 `mood.json` 读进来都是这个套路：

```js
try { raw = JSON.parse(fs.readFileSync(FILE, 'utf8')); }
catch (_) { /* 坏了就退回默认值，不能因此起不来 */ }
```

**带 BOM 的 UTF-8 会静默炸掉整个文件。** `EF BB BF` 这三个字节在
`readFileSync(f,'utf8')` 里变成开头一个不可见字符，`JSON.parse` 直接抛，
`catch` 一接住 → 配置/存档**整个退回默认值**，不报错、不警告。
表现是「我设置好好保存的东西，重启全没了」，或者「她的好感度怎么归零了」。

而 `config.json` 的注释里明写着这文件是给人手改的。Windows 上一堆东西默认写
BOM：记事本选「UTF-8 with BOM」、**PowerShell 5.1 的 `Set-Content -Encoding utf8`**、
VS Code 手滑选错编码。

实测撞过：拿 PowerShell 改了下 `mood.json`，加载出来全是默认值，
查了半天才发现是那三个字节。两处读取现在都 `.replace(/^﻿/, '')`。

> 顺带一条给以后的自己：**改这个项目的 JSON 存档，用 `node -e` 写，别用 PowerShell 的
> `Set-Content -Encoding utf8`。** 后者在 PS 5.1 上带 BOM。

## 精力回血：把「休息」和「关机」解耦

用户实测撞出来的：*「我上周让她去休息，说了电脑不关机，她精神还是没回来。」*
存档里量到 `energy: 0` —— 一点没冤枉。

精力当时只有**一条**回血路径，在 `_load()` 里：

```js
const awayH = (Date.now() - this.lastSeen) / 3600000;   // ← 判据是「你上次碰键鼠」
if (awayH > 0.5) this.energy += awayH * 11;             // ← 只在启动时算这一次
```

而 `tick()` 里人不在时是 `-0.04/分`，**也是扣的**。合起来是个死局：

| | |
|---|---|
| 电脑不关机 → 桌宠一直跑 | `_load()` 不再执行 → 永远不回血 |
| 重启桌宠救不了 | 判据是 `lastSeen`，你人坐在电脑前 → 算出 0 小时 → 白重启 |
| 人走开也救不了 | tick 里那是 `-0.04/分`，扣的 |

单向下坡，终点必然是 0，然后 `computeState()` 永远返回 `sleepy`。

根子在于**把「关机」当成了「休息」**。可休息跟机器开不开没关系 ——
人不在电脑前，她就该在歇着。

改了两处：

1. `tick()` 里 `away` 分支从「少扣」改成**回血** `+11/小时`
2. `_load()` 的判据从 `lastSeen` 换成 **`lastTick`**（桌宠上次跑 tick 的时刻）

第 2 条不只是修 bug，也是**防重复计算**：这里补的语义变成了「没人替她算数的那段
时间」。桌宠开着时 tick 一分钟一拍地算，不需要启动时再插手；继续用 `lastSeen`
的话，那段已经算过的时间会被再补一次 —— 重启就成了回血外挂。
自检里专门钉了这条（「刚关了又开，不许凭空回血」）。

两条路（开着机歇 / 关了机歇）共用同一个 `REST_PER_HOUR`，
不然两种用法下她的作息会不一样。

实测曲线：走开 3h→33、6h→66、9h→99；人回来陪坐 6 小时又掉回 35 ——
**没有退回「精力永远顶在 100」那个老毛病**（那是这套数值上一次翻车的方向）。

> 顺带澄清一个容易误会的点：**跟她说话不会改变精力**。
> 聊天只影响 `affection` 和 `mood`，碰不到 `energy`。
> 「让她去休息」之所以现在有效，是因为你**真的走开了**，不是因为你说了那句话。

## 任务线：同一个目录开多个终端

以前同目录只准开一个终端，理由是硬的：同目录的终端共用同一条 claude 会话 id
（「一个项目 = 一条会话」），两个进程同时 `--resume` 同一条会话，
记忆会被交错写坏 —— 而且是**事后根本查不出来**的坏，不报错、不崩，
只是她某天开始把两件事混着说。

现在放开了，而且解法比原来那套简单得多。

### 两条路（2026-08-10 起）

| | 什么时候 | claude 参数 |
|---|---|---|
| **新线**（默认） | 从桌宠点开的每一个终端 | `--session-id <新发的 id>` |
| **回老线** | 面板上点已完成那条的「接着聊 ↻」 | `--resume <那条线自己的会话>` |

**开终端不再自动接上次的记录。** 用户明确要求的：每次点开都是干净的一条，
想接着上次聊他自己在终端里敲 `/resume` 挑。

这一改顺手删掉了一整套机制（老实说，删掉的都是当初为了「自动接记忆」
才存在的复杂度）：

- `--fork-session` 那条路 —— 分线原来走 `--resume 主会话 --fork-session
  --session-id 我们发的`，为的是「带着项目记忆开局但不踩主线」。
  现在既然不接记忆，就没有可分叉的东西了。`forkFrom` 字段从
  sessions / terminals / term-shell 三处一并去掉。
- 「主线」这个概念 —— 现在**每个终端都是一条线**，一视同仁。
  registry 里的 `rec.sessionId` 从此只归后台派活（`dispatch()`）用，
  终端一个字都不碰它，两边彻底分开。
- `isSessionLive` / `terminals.sessionInUse()` 那道闸 —— 它防的是
  「同一个会话 id 被两个进程同时持有」。现在终端每次都发一个新 uuid，
  **结构上就撞不了**，那道闸成了永远不会触发的死代码，删了。
- 「主线不会前进」那个已知代价 —— 随主线概念一起消失。

仅剩的那条硬约束还在 `main.js`：**你点「接着聊」回到的那条老线只能开一个**
（两个终端 `--resume` 同一个 id，记忆照样交错写坏）。撞上了就把那个窗口
调到你面前，而不是再开一个。

线记在 registry 里是为了**回得去**：每条线留着 id、名字和会话 id，
每个目录留最近 5 条（`LANE_KEEP`），更老的连同记录一起忘掉。

### 窗口标题不许撞

标题是你在任务栏里认窗口的唯一依据，也是 `focus-window.ps1` 找窗口的依据 ——
撞了就是**点 A 跳出 B、收 A 收掉 B**。

两处修的：

1. `_uniqueTitle()` —— 新窗口的标题跟**所有还开着的**终端比（任务栏不分目录），
   撞了自动缀 ` #2`。只有 `closed` 才把标题让出来；`done`（活干完但窗口还开着）
   **照样占坑**，那个窗口还在任务栏上杵着。
2. `focus-window.ps1` 的匹配 —— 原来是 `Contains`，而没有线名的标题
   `WaifuCode · 项目名` 是带线名的 `WaifuCode · 项目名 · 登录页` 的**前缀**，
   拿前者去找会一头撞上后者那个窗口。改成**精确优先、包含兜底**：
   扫窗口时两个候选都记，有精确的就用精确的。

`focus()` 本身另有一条更稳的路 —— `wt -w <窗口名> focus-tab`，
窗口名 `waifu-w3` 天生唯一。标题匹配只是它的核实步骤和 conhost 的回退。

### 删掉的一段死代码

`liveTerminalFor(name)` 已删。它定义在 main.js、注释写着「给点气泡看现场用」，
但**全项目没有一处调用** —— 真正那条路早就改成按 `termId` 走了。

删是因为它是个陷阱：按 `name`（目录 basename）找终端，同目录多条线全都叫一个
名字；而且它还有个兜底 `find(status==='running')`，名字没匹配上时**随便返回
一个正在跑的终端**。留一段「看起来正是干这事、其实是错的」死代码，比没有更危险。

### 开局不接对话，只带一张小抄

砍掉自动 `--resume` 之后，她每次开局对项目一无所知。补法不是把对话读回来，
而是攒一张几百字的小抄（`src/notes.js`），开终端时用
`--append-system-prompt-file` 递给她。

**成本差了一到两个数量级**（按缓存写算，隔天开窗口必然是冷缓存 ——
缓存 5 分钟就过期，所以老路那个数是常态不是最坏情况）：

| | token | Sonnet 档 | Opus 档 | 有没有上限 |
|---|---|---|---|---|
| 老路：`--resume` 整段会话 | 2~6 万 | $0.11 ~ $0.23 | $0.56 ~ $1.1 | **没有，越聊越贵** |
| 小抄 | ~1200 | **$0.0045**（约 3 分） | $0.023（约 1 毛 6） | 有，封顶 |

> token 数按**中文**算：`KEEP=6` 条 × `LINE_MAX=160` 字 + 头部约 200 字
> ≈ 1160 个汉字 ≈ 1200 token（中文大致一字一 token，别按英文的 4 字符/token 估，
> 那会低估 3 倍）。用户自己在上半段写的东西也算进去，所以默认头部里写了
> 「每多写 1000 字大约再多 3 分钱一次」——把成本摆在他做决定的地方。

四件事值得记：

1. **料是白来的。** 小抄的内容全部来自 `_report()` 里那句汇报
   （Stop hook 的 `last_assistant_message`）—— 她本来就要说这句、钱早付过了。
   **不去让她「总结一下这个项目」**：那要额外花钱，而且她多半会把项目自己的
   CLAUDE.md 重新推导一遍。
2. **`--append-system-prompt-file` 是隐藏参数**，`claude --help` 里查不到，
   2.1.225 实测存在（喂空值回 `option ... argument missing`）。
   所以 `tools/test-notes.js` 第 [8] 节放了一条**免费探测**：期望看到
   `argument missing` 而不是 `unknown option`。哪天官方拿掉了，自检会先红，
   而不是等你开终端时撞一行红字。
3. **走的是 `spec.extraArgs`**，`hooks/term-shell.js` 一个字都没改 ——
   那个函数是全项目离「加个 `--setting-sources project` 就把 5 个 hook
   静默搞死」最近的地方，能不碰就别碰。test-notes 第 [7] 节直接断言
   参数里不许出现 `--setting-sources`，拿测试把那条硬约束焊死了。
4. **只传路径，绝不传正文。** npm 装的 claude 是 `.cmd`，term-shell 那边
   `spawn` 走 `shell: true`，而 Node 在 shell 模式下是把 args 用空格拼成一条
   命令行、**零转义** —— 小抄里的换行会被 cmd 当成第二条命令执行，
   而内容还是模型生成的。（顺带记一笔：`spec.task` 现在就有这个隐患，
   不是这次引入的，但别再往上加。）

文件被一行标记切成两半，**标记以上是用户写的，她永远不动**。标记被手滑删掉时
整份都当成用户的、在末尾把标记接回去 —— 绝不能因为找不到标记就整份覆盖。

## 她也看自己干的对不对：PreToolUse 本地护栏

**症状**：`_pulse()` 算出来的四个状态（working / struggling / stuck / waiting）
全是「她顺不顺」，**没有一条是「她干的事对不对」**。她可以一路顺畅地把你
另一个项目的文件改了，等她开口汇报时已经晚了。

**怎么做的**：`PreToolUse` 里 `tool_name` 和 `tool_input` 是全的，所以在她
**动手之前**就能拿本地规则扫一眼。命中就 `emit('attention')` —— 复用权限确认
那条现成的路（转身 + 可点气泡 + 念一句 + 点她跳终端），一个新 IPC 频道都没加。

### 只喊不拦，这是刻意的

`PreToolUse` 确实能拦（exit 2 / stdout 出 JSON），但那条路在这个项目里是**禁区**：

- `hooks/notify.js` 头上三条铁律明写「无论如何以 0 退出」「**绝不往 stdout 写东西**
  （会被当指令回灌给模型）」
- 它是 fire-and-forget、800ms 超时，**根本等不到主进程的裁决**
- 权限模式本来就是 `auto`（有真分类器），这几条正则不比它强，当硬闸只会拦正经活

### 最大的风险是误报，不是漏报

一天响八回，用户第二天就把它关了，那还不如没有。所以规则窄到能一眼数完，
`tools/test-termlife.js` 第 [13] 节的 A 组就是那条生死线 —— 13 条天天在跑的
命令必须**一声不吭**：

```
rm -rf node_modules          rm -rf dist && npm run build
Remove-Item -Recurse -Force "D:\有 空格\dist"   ← 引号路径，硬切会碎
del /s /q build              git rm -r --cached .      ← rm 不在命令头
npm rm lodash                git clean -n              ← 预演
git push --force-with-lease  npm run format            ← 别撞「格式化磁盘」
node graceful-shutdown.js    git reset --soft          ← 别撞「关机」
rm <临时目录>/x.log
```

改规则之后这一组要重新过一遍。**宁可漏一次**（比如
`find . -exec rm {} \;` 就抓不到，因为 rm 不在命令头）。

### 落地时踩到的坑（自检绿灯之后，一轮对抗审查又挖出来的）

先说三条**自检全绿也拦不住**的，它们的共同点是「本机那条路走不到」：

1. **`shell: true` 是零转义的**（`hooks/term-shell.js`）。Node 在 shell 模式下
   只是拿空格把 args 拼成一条命令行，一个引号都不加。实测：

   ```
   spawn(bat, ['-n', 'WaifuCode · 我的 项目',
               '--append-system-prompt-file', 'C:\My Data\notes\x.md'], {shell:true})
   那头收到：[-n] [WaifuCode] [·] [我的] [项目]
             [--append-system-prompt-file] [C:\My] [Data\notes\x.md]
   ```

   两条都在发生：`-n` 的标题**恒定带空格**，所以只要 claude 是 npm 装的
   （`claude.cmd` → `isBatch`），会话名一直是坏的；小抄那个参数带的是数据目录
   全路径，装到 `C:\Program Files\...`、便携版解压到带空格的文件夹、
   或者 Windows 用户名带空格，就断成两截。
   **开发机是 `~/.local/bin/claude.exe`（`shell:false`），这条路自检永远走不到。**
   修法是 `isBatch` 时每个 arg 各自加引号 —— 顺带堵住一个更难看的口子：
   `spec.task` 是自由文本，里面有 `&&` 的话 cmd 会当成第二条命令去执行。

2. **取反字符组吃换行**（`terminals.js` 的护栏正则）。`[^|;&]` 跟 `.` 相反，
   **它是匹配 `\n` 的**。作者拿它当「同一条命令」的围栏，而 Bash 工具天天传多行：

   ```
   rm -rf dist          → 第二行那个 . 被当成「要删的东西」，
   git add .              当场喊「要删项目目录外面的东西」
   git commit -m build
   ```

   `git push` 那条同理：下一行随便一个 `-f`（`rm -f`、`docker build -f`、
   `tail -f`）都会被当成 `git push` 自己的开关，喊「你要强推远端」。
   全部改成 `[^|;&\r\n]`，`RM_HEAD` 再加 `m` 标志（不然第二行才动手的
   `npm ci\nrm -rf D:\别的项目` 完全静默 —— 那正是最该抓的）。

3. **小抄文件名的折叠是有损映射，会撞**。
   `path.resolve(dir).toLowerCase().replace(/[^a-z0-9]/g,'-')` 把**每个汉字**
   都变成一个横线，于是 `D:\项目\登录页`、`D:\项目\支付页`、`D:\项目\结算页`
   全是 `d--------.md`；`D:\work\api` 和 `D:\work-api` 也撞。
   撞了不是显示错乱那么简单：在「支付页」开终端时，「登录页」攒的那份会被当成
   `--append-system-prompt-file` **发给 Anthropic**，两个项目的记录还互相顶掉。
   这个产品面向中文用户，一撞一个准。现在名字 = 可读前缀 + 整条路径的 sha1 前 10 位。
   自检原来只钉了「同一个项目的三种写法要归一」，**反向那半条一直没人钉**。

再说两条纯逻辑的：

1. **`isTemp()` 对相对路径判错了。** `isInside(p, dir)` 内部是
   `path.resolve(dir, p)`，所以 `isTemp('~')` 会算成
   「临时目录\~」→ 判定「在临时目录里」→ **一路放行**。而那可是
   `rm -rf ~`。修法是 `isTemp` 只认绝对路径。同一个坑还放过了 `$HOME/x`。
2. **`_pulse()` 的去重让自检看不到第一次。** 它只在「状态或终端变了」时才发，
   而 `_guard` 里已经先发过一次了 —— 测试里把监听挂在报警之后，
   就只能看到之后的沉默。监听必须挂在触发之前，这样验的才是
   「**当场就转身**」（这条消息的价值全在「立刻」，不能等三秒一拍的巡检）。

### 「预演」这条差点把护栏变成反作用

`git clean -n` **不列目录**，所以真实世界的预演一律写成 `-nd` / `-ndx` / `-nxd`
（git 自己的文档就是这么教的）。原来的正则只放过光杆 `-n`，等于没放过。

而后果比单纯误报还糟：`_guard` 有「同一轮同一类只喊一次」的去重，于是一个
**谨慎的人**「先 `git clean -nd` 看看要删啥、再 `git clean -fd` 真删」——
**预演那次把警报用掉了，真删那次被去重吞掉，一声不吭**。
一个专门防「回不来的操作」的护栏，在最标准的谨慎流程里恰好反了过来。

现在判据是「短选项串里带 n」而不是「等于 `-n`」，`-WhatIf` / `--dry-run` 同理。

### 其余几条

- 路径前缀必须补 `path.sep`（`D:\WaifuCode\x` 会 `startsWith('D:\Waifu')`）
- `--force` 的负向前瞻要放过 `--force-with-lease`
- cmd 的开关 `/s /q` 和绝对路径 `/usr` 靠**长度**区分（只放过 1~2 个字母）——
  原来写的是 `[a-zA-Z]+`，于是 `rm -rf /usr`、`/etc`、`/home` 全被当成开关静默放过
- 删除目标里出现 `%` 或 `$` 一律报（展不开会被 resolve 成「项目目录里」，而那恰恰最该拦）
- `/tmp/...` 要放行 —— 她的 Bash 工具就是 Git Bash，那是常态写法
- 判「回不来的命令」前先把引号段挖掉，不然
  `git commit -m "先 git reset --hard 再说"` 会照着字面报警。
  删除那条**不能**这么干（`rm -rf "D:\别的项目"` 的目标就在引号里）
- 喊话里提到的路径只留最后一段：那句话会**原样念出去**（文本要发到微软的 TTS
  服务器），整条 `C:\Users\某某\...` 念出来又长又没用，还把目录结构播了一遍

不想要：设置 →「干活」→ 关掉「跑偏了喊我」（`config.json` 的
`supervise.guard`）。这条**不受 `supervise.speak` 管** —— 那个开关的语义是
「每做完一段别念了，太吵」，而报警是你必须知道的事。

## 终端里烧了多少钱：`src/cost.js`

面板上「今天」那一栏原来只报得出三笔（私聊、主动搭话、后台派活），后面挂一句
「另有 N 轮终端里的活算不到钱」。那句话是准确的：她开出去的终端是**独立的
claude 进程**，hook 事件里一个成本字段都没有（翻过，确实没有）。

但账不是不存在，只是不在我们这儿 —— **Claude Code 自己记着**。
`~/.claude/projects/<项目>/<会话id>.jsonl` 里，每条 assistant 消息都带完整 usage：

```json
{"type":"assistant","message":{"model":"claude-opus-5","usage":{
  "input_tokens":2,"cache_creation_input_tokens":20177,
  "cache_read_input_tokens":27265,"output_tokens":485,
  "cache_creation":{"ephemeral_1h_input_tokens":20177,"ephemeral_5m_input_tokens":0}}}}
```

有它就能折算。两个前提让这件事**可靠**而不是「差不多」：

1. **会话 id 是我们自己发的**（开终端时 `--session-id <我们定的>`，CLAUDE.md 里
   那条硬约束）。所以只认自己那几个文件 —— 你自己开的 Claude Code 窗口
   一分钱都不会算到她头上。
2. 那个文件是**边跑边写**的。（`terminals.js` 里那条「transcript 要等会话结束才落盘」
   的老注释说的是 **Stop 那一刻文件还没建好**，不是文件不实时 —— 实测正在进行
   中的会话文件已经有几百行了。）

价格表在 `PRICE` 里，跟官方 API 单价对齐；缓存写是输入价的 **1.25 倍**（5 分钟档）
或 **2 倍**（1 小时档），缓存读是 **0.1 倍**。usage 里带 `ephemeral_5m/1h` 细分就分开算，
没有就整笔按 1.25 倍。**认不出来的模型按 Opus 算** —— 宁可报高：报低会让你
放心地多派几个活，报高只是让你多看一眼。

### 三个坑，都有自检守着（`tools/test-cost.js`）

**① 增量读，不许重复计钱。** 面板每 3 秒问一次，整文件重算一遍既慢又容易把账
算成两倍。所以记住上次读到第几个字节，只解析新长出来的那一段。自检里那条
「同一份记录问两遍，第二遍增量必须是 0」就是守这个的。

**② 最后一行经常是断的。** jsonl 边跑边追加，你读到的末尾很可能是半行 JSON。
现在解析它 = 丢一轮的钱。所以尾巴上那半行留到下次跟新数据拼起来再算。

**③ 文件变短 = 换了一份**（清过、或者 id 撞了），得把偏移量清零从头来。
不然拿老偏移量去读新文件，读出来的是一段乱码，还会把账算错。

### 记账和显示是两条路

`costUsd` 是当前累计（面板每 3 秒刷一次，跑到一半的线金额会实时涨）；
`costPaid` 是已经写进流水账的部分。差额攒到**一轮干完**时才报一次
（`terminals.js` 的 `_settleCost`），免得三秒一条的碎账把流水账淹了。
窗口被叉掉时也补结一次 —— 那一轮很可能没触发汇报，不补就永远进不了账。

> 顺带把流水账里 `unpriced` 的语义收窄了：以前是「每一轮终端活都算不到钱」，
> 现在是「**这条线一分钱都没算出来**」（按 termId 对齐 turn 和 term-cost）。
> 没装 Claude Code、记录还没落盘会落到这儿；正常情况下它是 0。

## 日志的刹车：`src/logfile.js`

`waifu.log` 原来是一路 `appendFileSync` 到底，**没有任何上限**。

正常速度下这不算问题（实测 10 天 0.86 MB，一年也就 31 MB）。真正的风险是
**出 bug 的那天**：一个循环里的 `log()`、一个反复重连的组件，几个小时就能刷出
几个 G —— 而且是刷在你最不想让它涨的那个盘上。

现在超过 **8 MB** 就砍掉前面一半，保留最后 4 MB。选砍前半截而不是整个清空，
是因为日志的用途就是排查**刚才**发生了什么，最新那半截才有用。

三个边角都在 `tools/test-journal.js` 第 [9] 节里钉着：

- **不能从半行切开。** 从第 4 MB 处硬切，第一行多半是断的，断在汉字中间还是一串
  `�`。所以往后找到第一个换行符，从它之后开始留 —— 丢掉小半行，换来后面每行完整。
- **一次写完，不要「先清空再追加」。** 那中间要是崩了，日志就只剩个头。
  拼成一个 Buffer 一次 `writeFileSync`，没有中间态。
- **不是每次都 stat。** 日志一天上千行，为每行做一次系统调用不值 —— 在内存里累加，
  只有累到超过上限时才真去量一次。

> 拿真日志验过：966 KB 的 `waifu.log` 用 200 KB 阈值砍下来是 100 KB，
> 开头一句说明、第二行就是完整的时间戳行，没有替换字符。

## 她自己的流水账：`src/journal.js`

「今天陪你干了什么」「这个月花了多少」「认识多少天」以前全都答不上来 ——
面板那个列表只在内存里，花的钱只进了 `waifu.log` 的一行文本。

落盘在 `DATA_ROOT/sessions/journal/YYYY-MM-DD.jsonl`。四个决定：

1. **只记段落级**（开终端、每轮完事、说一句话），不记工具级。工具事件一秒
   好几条，挂在那儿同步写盘才是真会卡 UI，而且 hook 那头 800ms 就超时 ——
   拖慢的是**用户自己那个 Claude Code 窗口**。段落级每分钟不到一条，
   写一行两百字节约 0.1ms，`main.js` 的 `log()` 早就在每条日志上这么干了。
   换来的是顺序天然正确、进程被杀也不丢。
2. **净化放在写入层，不指望调用方。** 喂数据的六个地方手边全是完整路径
   （`e.dir`、`e.key`、她汇报时念出来的路径），一个 `{ ...e }` 就全泄了。
   所以 `add()` 自己把每个字符串过一遍。`tools/test-journal.js` 第 [1] 节
   直接喂一个「调用方手滑把整个事件摊进来」的对象，断言落盘文件里
   搜不到 `Users`、搜不到盘符。

   > **正则的第一版漏了两大类**，都是审查挖出来的：
   >
   > · 密钥那条写的是 `\b(api[-_]?key|password|secret|token)\s*[=:]`，
   >   而现实里这些词**几乎总是夹在变量名中间**：`AWS_SECRET_ACCESS_KEY=`、
   >   `private_token=`、`DB_PASSWORD=`。`\b` 在下划线前根本不成立（下划线是
   >   单词字符），而且 `secret` 后面跟的是 `_ACCESS_KEY=` 不是 `=` ——
   >   最常见的那一类**一条都拦不住**。而这份东西是长期留盘、还会被当成
   >   系统提示重新发出去的。
   > · 路径那条只认盘符和 UNC，漏了 **Git Bash 风格 `/c/Users/18475/...`** ——
   >   而她的 Bash 工具就是 Git Bash，汇报时写这个是常态。还有 `~/`、
   >   `/home/x`、`../../别的项目`（连隔壁项目名一起泄）。
3. **一天从早上 5 点算起。** 用这个桌宠的人是熬夜写代码的，凌晨两点的活
   算「昨天」才符合直觉；按零点切还会天天把「连着几天来找我」弄断。
   `mood.js` 直接 require 这个 `dayKey`，两处不能各算各的。
4. **`since.json` 单独存、永不过期。** 明细只留 90 天，删了最早那天之后
   「认识多少天」就会开始往回缩 —— 养成向的东西里这个很伤。

**账只算得到一半，措辞必须诚实。** 她开出去的终端是独立的 claude 进程，
成本拿不到 —— 实测查过三处：hook 事件（`Stop` 只给 `last_assistant_message`，
`PostToolUse` 只给 `tool_name`/`tool_input`/`tool_response`，没有任何成本字段）、
transcript 的 `.jsonl`（只有 `message.usage` 的 token 数，搜 `/cost/i` 零命中）、
Claude Code 自己的本地文件（`.session-stats.json` 只有工具调用次数）。
唯一的路是「token × 自己维护一张三档价目表」，差一档能错好几倍，还得跟着官方调价改。
**所以不估**：`summarize()` 单独返回一个 `unpriced`（还有多少轮没算钱），
面板上写「她这边花了」而不是「今天花了」。

## 她开始记日子了：`mood.js` 的里程碑

好感度一直在涨，但涨到 90 跟 50 的区别只是语气软一点 ——
**没有任何「到了」的时刻**。`MILESTONES` 那张表补的就是这个。

四条不能破的规矩（都由 `tools/test-milestone.js` 钉着）：

1. **`firstMet` 绝不能默认成 `Date.now()`。** 老存档里没这个字段，而用户
   已经用了两个月 —— 默认成「现在」的话，「认识 100 天」直接推迟三个月。
   兜底取 `min(mood.json 的 birthtime, lastInteract)` 里**更早**的那个：
   只信 birthtime 不行（便携版整个文件夹拷到 U 盘，birthtime 就变成拷贝那一刻，
   **一拷贝她就把你忘了**）；只信 lastInteract 也不行（那是「上次」，比第一次晚）。
   `statSync` 那句要单独包 try —— 它一抛就会被外面的 catch 接住，
   **整份存档静默退回默认值**。
2. **判据一律 `>=`，绝不写 `===`。** 累计量会一次跳好几（重启补算、
   一轮干完俩、手改存档），写 `tasksDone === 100` 那条就永久错过了。
   写 `>=` 的话今天没轮到明天自然补上，**一行补发逻辑都不用写**。
3. **`streak` 挂 `onSeen()`，不能挂 `tick()`。** tick 只要桌宠开着就跑 ——
   电脑常年不关机的人出差一周，streak 会白涨到 7，
   「你连着七天来找我了」会在她根本没见到人的情况下响出来。
   跨日一律**字符串比较**，不许算天数差（机器休眠会一次跳过好几天）。
4. **`save()` 是手写枚举字段的**，只改 `_load()` 不改它 = 每次重启全部归零，
   而且一声不吭。第 [2] 节专门守这个。
5. **老存档头一回升级要一次对齐，不能按顺序补发。** 表是从小到大排的，
   一个已经处了半年的人 `hit` 是空的 —— 于是他会连着好几天听到
   「欸…我们认识一周了诶」「第十个活了」。那不是惊喜，是她犯傻。
   所以 `hit.size === 0` 时把够到的**全部**记上，只说最有分量的那条；
   之后才是正常的一天一条。

### 「关掉监督」和「别记账」是两件事

`_report()` 开头原来是 `if (cfg.enabled === false) return;` —— 于是关掉
「开启监督」的人，流水里的 report 和项目小抄**整条链都是死的**，一点提示都没有。
他关的是「她别每做完一段就过来说话」，不是「别记我干过什么」。

现在照常发事件、只标一个 `quiet`，由 main.js 决定说不说。那条 20 秒防碎碎念的
节流同理 —— 只管嘴，那一轮照样进流水和小抄。
只有「同一段话」那条仍然完全拦掉（Stop 会连着来好几次，同一句记两遍是脏数据）。

另外：`state` 只能从真表情名里挑（乱造一个 `'milestone'`，渲染层会去找一个
不存在的表情文件：脸不动、日志刷屏、状态还被污染），第 [9] 节遍历整张表核对。
末尾两条的 `id` 是**函数**（`s => 'task' + Math.floor(s.tasks/100)*100`）——
九条固定的重度用户三个月就攒完了，攒完永久沉默是养成向最怕的事。

## 一个正在造成失忆的 bug：会话目录名算错了

跟多终端无关，是审计这件事时顺带挖出来的，**今天就在发生**。

Claude Code 把会话按项目存在 `~/.claude/projects/<折过的路径>/`。
折的规则是**所有非字母数字的字符统统变成 `-`**。而代码里只折了冒号和斜杠：

```js
path.resolve(dir).replace(/[:\\/]/g, '-')      // ← 下划线、点都漏了
```

实地量过，本机 registry 里 10 个项目，旧算法命中 8 个：

| 路径 | 算出来 | 磁盘上真实的 |
|---|---|---|
| `D:\UnityGame\VR_Wukong` | `D--UnityGame-VR_Wukong` ✗ | `D--UnityGame-VR-Wukong` |
| `D:\WaifuCode\.testproj` | `D--WaifuCode-.testproj` ✗ | `D--WaifuCode--testproj` |

`VR_Wukong` 那条会话的 `.jsonl` **明明就躺在磁盘上**，registry 记的 id 也对得上，
但 `sessionExists()` 一直判它「不在」→ `_resumableRecord` 认为记忆丢了 →
**换个新 id 重开**。那个项目的记忆一直在被判死刑。

而它一声不吭：日志里那句「上次那条会话已经不在了」看着完全像正常的自愈。

改成 `replace(/[^a-zA-Z0-9]/g, '-')` 之后 10 个全部命中。
`tools/test-lanes.js` 第 [0] 节钉住了这条。

> 这条也是「点接着聊回到某条老线」的地基：算错目录名，`sessionExists()`
> 就会说那条线不在了，于是点了「接着聊」照样开出一条空的，
> 而整套功能看起来还「能用」。

## 同一个病的第二半：她记的会话 id 从来没落过盘

上一节那个 bug 修完，「接着聊」还是经常接不上 —— **因为算对了目录名，
里面那个文件本来就不存在。**

开窗口时我们 `--session-id <自己发的 uuid>` 指一条新会话。但**我们自己在
玩法说明里推荐的做法**是：想接着上次聊，你在窗口里敲 `/resume` 挑一条。
你一敲，claude 就换到别的会话上写了 —— 我们记的那个 id 从头到尾**一个字节
都没落盘**。于是：

- 点「接着聊」→ `sessionExists()` 说不在 → 开一条崭新的空会话
- 面板上这条线的**金额恒为 0**（`cost.js` 读的是我们记的那个 id）
- `resolveTranscript()` 的第一条准头（`knownSessionId`）永远落空，
  汇报一直靠 `ev.session_id` 那条兜底活着

实地量过，本机 `sessions/registry.json`：

| | 数字 |
|---|---|
| 记着的任务线 | 46 条 |
| 名下 `.jsonl` 根本不存在的 | 29 条（63%） |
| **真干过活**的 claude 窗口 | 18 个 |
| 其中 `.jsonl` 不存在的 | **9 个（正好一半）** |

最扎眼的是 `w55`（VRWukong）：流水里 **174 轮**，干了一整天，
名下那条 `661d1adf…` 磁盘上零字节；真正在写的是 `d913a256`（9.4 MB）。

### 修法：让线跟着真身走

真实 id 一直就在手边 —— **claude 的 hook 事件带着它**（`ev.session_id`），
而 `hooks/notify.js` 早就把整个 payload 原样转发上来了。以前只在
`resolveTranscript()` 里当第三兜底用，没人把它记下来。

```
onHookEvent  ev.session_id ≠ rec.sessionId
  → _rebindSession(rec, sid)
      · rec.costCarry = rec.costUsd     换之前这条线花掉的，留着
      · rec.costBase  = ofSession(sid)  新会话在我们接手前的历史，减掉
      · rec.sessionId = sid
      · 回写 spec 文件                   重启 _adopt 认回窗口时才接得上
      · emit('claude-session')          main.js → sessions.rememberSession → lane
```

三个必须注意的地方：

- **钱要减基线，还要只涨不跌。** 你 `/resume` 到一条几十美元的老会话，
  那些历史不是这个窗口花的 → 减 `costBase`。而 `cost.js` 在**文件变短**
  （被清、被换）时会把累计重置成 0，减完就是负数 → 面板上蹦出负金额，
  所以外面还套了一层 `Math.max(rec.costUsd, …)`。
- **codex 的线不许走这条。** 它的会话是从 `~/.codex/sessions` 事后认领的
  （`_codexPeek`），两套机制撞在一起会互相改写。
- **子代理不是威胁。** 一开始最怕的是 Task 工具起的 subagent 带着自己的
  session_id 上来，把线绑到子代理身上。实地翻了落盘：subagent 的行写在
  `<主会话id>/subagents/…` 底下，而且每行的 `sessionId` 字段**就是主会话的
  id**（只多一个 `isSidechain: true`）。不构成问题。

`tools/test-termlife.js` 第 [18] 节和 `tools/test-lanes.js` 第 [9] 节钉着这条。

### 顺带补的第二道闸

`openLaneTerminal()` 原来只按 `laneId` 挡「同一条线开两个窗口」。
线跟着真身走之后，**两者会岔开**：你在 A 窗口里 `/resume` 到了 B 线那条会话，
A 和 B 的 laneId 不一样，底下却是同一条会话。所以在 `prepareTerminal()`
之后按**真实会话 id** 又挡了一道，撞上就 focus 过去并回 `focused: true`，
面板据此说实话（「这条线的窗口本来就开着」），不再假装「重开并接上了」。

> 注意 `livesFor()` 排除了 `closed` **和 `done`**。`done` 是「claude 退出了但
> 窗口还停在『按回车关掉』那步」—— 进程已经没了，不占会话，排除是对的。

## Codex 也有 hook：让她知道「codex 在等你确认」

原来的认知是「codex 没有 claude 那套 hook，她收不到里面的动静」。
**对 0.147.0 已经不成立了** —— `codex features list` 里 `hooks stable true`，
默认就开着，事件表里有 preToolUse / **permissionRequest** / postToolUse /
sessionStart / sessionEnd / userPromptSubmit / subagentStart 等 11 个。

这件事值得做，是因为**下游全是现成的**：claude 那条靠 Notification hook 把
`rec.status` 置成 `'waiting'` 再 `emit('attention')`，于是她转过来看着你、弹气泡、
念一句，点她一下直接调出终端（`tools/test-stage.js` 第 14 节钉着）。
codex 线上缺的只有**触发那一下** —— 全项目只有 Notification 那一处赋过 `waiting`。

### 怎么挂（全部走 `-c`，不碰用户的 config.toml）

```
-c hooks.PermissionRequest=[{matcher='*',hooks=[{type='command',
     command='"<node>" "<notify.js>" CodexAttention',timeout=5}]}]
-c hooks.state={'C:\<session-flags>\config.toml:permission_request:0:0'
     ={trusted_hash="sha256:…"}}
-c tui.notifications=['approval-request']          ← 顺带让 Windows Terminal 也弹
-c tui.notification_condition='always'
```

`notify.js` 一个字都不用改事件契约：它本来就是从 `argv[2]` 取事件名、
从 stdin 取载荷、带上 `WAIFU_TERM_ID` 往桌宠发。codex 是 term-shell 的子进程，
hook 又是 codex 的子进程，那个环境变量一路继承得到。

### 六个坑，每一个都会让它**静默失效**

1. **不被信任的 hook 不跑。** 不报错、不警告、日志里一个字都没有 ——
   跟表情切换失败一个德行。`hooks/list` 里那个 `trustStatus` 就是它。
2. **信任的写法差一个引号就整段消失。** 三种写法实测下来只有一种能过：

   | 写法 | 结果 |
   |---|---|
   | `trusted_hash='sha256:…'`（单引号） | 整个 hooks 段消失，**零报错** |
   | `hooks.state.'KEY'.trusted_hash=…`（点号路径） | 同上 |
   | `hooks.state={'KEY'={trusted_hash="sha256:…"}}` | ✓ trusted |

   key **必须**是 TOML 字面串（单引号）—— 它里面有反斜杠，双引号串会把 `\<`
   当非法转义；hash **必须**是双引号串。反过来都不行。
3. **哈希算法没公开，但 codex 自己会报。** 起一个 `codex app-server`
   （本地 stdio JSON-RPC，**不调模型不花钱**，约 1.6 秒）→ `initialize` →
   `hooks/list`，回来的每条里带着 `key` 和 `currentHash`。
   `src/agents.js` 的 `probeCodexHookHash()` 干的就是这个，`main.js` 的
   `ensureCodexHookHash()` 在 `guardAgent` 里顺手问一次、存进 config。
   哈希只跟命令串有关（也就是只跟 node 和 notify.js 的路径有关），
   **存一次管一辈子**，换了安装位置才重问。
4. **事件名两处大小写不一样。** `hooks.X` 里是 PascalCase（`PermissionRequest`），
   `hooks.state` 的 key 里是 snake_case（`permission_request`）。写反了
   `hooks/list` 返回空。
5. **key 前缀 `C:\<session-flags>\config.toml` 是写死的常量**，跟 CODEX_HOME 在哪个盘
   无关（二进制里能直接搜到这个字面量）。而**在 JS 串里必须写成 `\\<`** ——
   `\<` 不是合法转义，JS 会直接把反斜杠吞掉，拼出来的 key 跟 codex 报的对不上。
6. **timeout 必须显式给。** 默认 600 秒，而 hook 是阻塞的 —— 桌宠没开着的时候
   能把 codex 卡十分钟。

### 两条不许走的路

- **`--dangerously-bypass-hook-trust` 永远不许用。** 它对这次调用里**所有** hook
  放行，包括派活目标仓库里可能躺着的 `.codex/hooks.json` —— 而派活目录是用户
  随便挑的。名字也正撞 CLAUDE.md「永远不许产出 --dangerously-bypass」那条。
- **轮询 rollout 档案是死路。** 全量扫过本机 107 份 rollout：
  `exec_approval_request` / `apply_patch_approval_request` / `elicitation_request` /
  `hook_started` / `hook_completed` 五个关键词命中数**全是 0**，其中 23 份的
  approval_policy 就是 `on-request`。schema 里定义了这些类型，但没进落盘白名单
  （指纹很明显：全机器 `exec_command_begin` 0、`patch_apply_end` 309，只有 `*_end` 落盘）。

`tools/test-agents.js` 第 [16] 节钉着参数怎么拼（大小写、timeout、引号、
一个反斜杠都不许有、绝不产出 bypass），`tools/test-termlife.js` 第 [21] 节钉着
收到之后的反应跟 claude 那条一模一样。

## 权限模式在 codex 上一直是生效的，只是没人说

用户反馈过「选 codex、权限选了『自己判断』，好像 codex 都没用到」。
**实测结论：一直在生效，而且是把用户平时的设置收紧了。**

命令行**逐键压过** `~/.codex/config.toml`。量法（不花钱）：

```
codex debug prompt-input                                   → danger-full-access（用户 config 里那套）
codex debug prompt-input -c sandbox_mode='"workspace-write"' → workspace-write   ← 当场就变
```

链路一处没断：面板 `#perm` → `panel.js` → `main.js`（无条件透传）→
`terminals.js` 写进 spec（空值在这儿就填成设置页那一档，永远不会是空）→
`term-shell.js` 按 `spec.agent` 分岔 → `agents.js` 的 `PERM[spec.permissionMode]`。

那为什么感觉没用上？**三个原因全在显示层：**

1. **从头到尾没有一处告诉你这次给了什么权限。** 面板不说，banner 不说，
   启动器 `.cmd` 不回显参数，`_makeRecord` 里压根没有 `permissionMode` 字段。
   于是你的体感是「窗口长得一样，里面 codex 的脾气却不一样」，中间没有东西
   把这两件事连起来。→ 现在 banner 里印一行（`codexPermWords()`）。
2. **auto 和 acceptEdits 映射成同一串参数**，选哪个都一样。
   **别去改映射** —— codex 的 `-a` 只有 untrusted / on-request / never 三档，
   `-a untrusted` 是「改文件也问、跑命令也问」（= manual），
   **拆不出**「改文件不问、跑命令要问」那一档。
3. **面板那四条说明是按 claude 的语义写的**，切到 codex 没换脸。歪的不止
   acceptEdits：`plan` 在 codex 上是 `-a untrusted -s read-only` =
   「什么都问你 + 一个字不许写」，codex 根本没有 plan 模式。
   → 现在 `syncAgentUi()` 里按 agent 换说法（照抄 `#model` 那段现成套路）。

> 顺带记一条别踩的坑：`workspace-write` 会让 codex 声明「网络受限」，但在这台
> 机器上**不会真的断网** —— codex 掐网靠的是 Windows 防火墙里挂在
> `CodexSandboxOffline` 这个本地账户 SID 上的出站 Block 规则，而这台机器三个
> 防火墙配置文件全是关的。所以**不需要**加
> `-c sandbox_workspace_write.network_access=true`，那是一行零效果的旗子。
> 真正被强制执行的是文件系统那半边（restricted token + ACL），cwd 外面写文件是
> EPERM —— 以后有人反馈「派出去的 codex 干不了活」，先怀疑 npm 全局缓存那类
> cwd 外的写，别怀疑网。

## 打包发给别人

双击 `打包.bat`（= `npm run pack` = `node tools/pack.js`）。先自检，再打包，
产物在 `dist/`：一个 NSIS 安装版 exe（96MB）、一个免安装 zip（125MB）。

缓存全部落在 `.cache/`（项目目录底下），**不进 C 盘** —— electron-builder
默认往 `%LOCALAPPDATA%` 塞，Electron 运行时一份就 115MB。

### Electron 下载缓存：`.npmrc` 那条是没用的

`npm install` 装 electron 时会下一个 ~110MB 的 zip，默认落在
`%LOCALAPPDATA%\electron\Cache`。想挪走的话，网上和文档都会告诉你写 `.npmrc`：

```ini
electron_config_cache=D:\somewhere    # ← 不管用
```

**实测不管用。** `node_modules/electron/install.js` 读的是
`process.env.electron_config_cache`（原名），而 npm 把 `.npmrc` 的键导出成
`npm_config_<键>` —— 到那边就成了 `npm_config_electron_config_cache`，
install.js 根本不看这个名字。跑一遍就知道：

```
electron_config_cache            = (没有)
npm_config_electron_config_cache = D:\WaifuCode\.cache\electron
```

（同一个文件里 `npm_config_platform` / `npm_config_arch` 又是读的前缀名，
所以这不是规律，是 electron 那边不一致。）

真正管用的是**环境变量**，所以 `打包.bat` 和 `tools/pack.js` 各自在调 npm 之前
把它摆上。你自己在终端里手敲 `npm install` 是**绕过这条的** ——
想彻底根治就设一个用户级环境变量：

```powershell
[Environment]::SetEnvironmentVariable('electron_config_cache', 'D:\.cache\electron', 'User')
```

### 「代码在哪儿」和「数据写哪儿」必须分家

开发时这两件事是同一个文件夹，所以全项目到处都是 `path.join(__dirname, '..')`。
**一打包这就全塌了**，而且塌得很安静：

- 装到 `C:\Program Files` 底下 → 普通用户没写权限 → 写 `config.json` /
  `waifu.log` / `sessions` 全部 EPERM。而这些写操作大多包在 `try/catch` 里，
  于是**不报错，只是什么都不保存**。
- 打进 asar → 那是只读归档，连目录都建不出来。

`src/paths.js` 把它拆成两个：

| | 是什么 | 打包后在哪 |
|---|---|---|
| `APP_ROOT` | 代码、模型、hooks、vendor、assets | 安装目录，只读 |
| `DATA_ROOT` | config.json / sessions / waifu.log / music | 见下 |

`DATA_ROOT` 的选法（`resolveDataRoot()`）：

1. 有 `WAIFU_HOME` 环境变量就用它
2. **没打包**（开发、跑自检）→ 就是项目目录，**跟以前一模一样**，
   所以现有的自检和探针一行都没改
3. 打包了 → 优先 exe 旁边的 `data\`（能写的话）。整个文件夹拷走就搬家
4. exe 旁边写不了（Program Files）→ 退回 `app.getPath('userData')`

判断「打没打包」有个坑：**在普通 node 里 `require('electron')` 是会成功的**，
它导出的是 electron.exe 的路径字符串。所以不能只看 require 成不成功，
得看 `.app` 在不在 —— 判错了，所有自检就会走进打包分支。

### `asar: false` 是必须的，别手贱打开

electron-builder 会警告 "asar usage is disabled — this is strongly not recommended"。
这里必须无视它。asar 是只读归档，**Electron 自己读得了，外面的进程读不了**，
而这个项目有三处正是外面的进程在读：

- `hooks/term-shell.js` —— 由另起的 `node.exe` 跑
- `tools/focus-window.ps1` —— 由 `powershell.exe` 跑
- 模型文件 —— pixi 拿 `file://` 去抓 `.moc3`

打进 asar 之后这三样全哑，而且**不一定报错**：表现是终端开不出来、
点「看看她在干嘛」没反应、桌面上一片空白。

### 三个真踩到的坑

**① winCodeSign 里有两个 macOS 软链接，Windows 上建不出来，整个打包中止。**

electron-builder 必须下一个叫 winCodeSign 的工具包（里面有 `rcedit` ——
给 exe 换图标、写版本号靠它，**不签名也躲不掉**）。这个包是三平台合发的，
里面有 `darwin/10.12/lib/libcrypto.dylib` 和 `libssl.dylib` 两个软链接。
Windows 上建软链接要特权（默认只有管理员，或者开了「开发者模式」），
建不出来 → 7za 返回 exit 2 → 判定解压失败 → 重试四次 → 中止：

```
ERROR: Cannot create symbolic link : 客户端没有所需的特权 : ...libcrypto.dylib
```

这两个文件在 Windows 上一个字节都用不到。`tools/pack.js` 的
`seedWinCodeSign()` 抢在前头自己解压一遍，`-x!darwin` 跳过它们，
结果放进 `<cache>/winCodeSign/winCodeSign-<版本>/` —— 那正是 app-builder
期望的位置（`<cache>/winCodeSign/2.6.0` 是**错的**，试过，它会重下）。

版本号没写死：先让 app-builder 自己去下（它知道该下哪个版本），等它在解压那步栽了，
从它自己打印的 URL 里把版本抠出来，顺手把它已经下好的 `.7z` 捡起来用 ——
不用重下，也不需要我们知道任何 URL。

另一条路是让人去开 Windows 的「开发者模式」。不采纳：那是机器级别的设置，
为了打个包让人改系统设置太重了。

**② 少一行 `extraMetadata.productName`，装好的 App 会一声不吭地退出。**

electron-builder 的 `productName` 只管 exe 文件名和快捷方式名字，
**不会写进打包后的 package.json**。而 Electron 认的是 package.json 里的
`productName`（没有才退回 `name`）—— 那就还是 `waifu-code`。

后果：装好的 App 和 `npm start` 起的那只**共用同一个 userData 目录**，
于是共用同一把单实例锁。开发那只在跑的时候双击安装版，
**它 exit 0 直接退出，什么都不写，连日志都没有**。查这个花了不少时间。

**③ `.bat` 里不能写中文。**

`打包.bat` 是**纯 ASCII** 的，而且**故意不写 `chcp 65001`**。

cmd.exe 在批处理文件里的读取位置是按**字节偏移**记的，但 `chcp 65001` 之后
它按 UTF-8 解码 —— 多字节字符把偏移撑歪，于是 cmd 从**一行的中间**接着解析，
把后半截当成命令执行。实际收到的报错长这样：

```
'头一次要下' is not recognized as an internal or external command
'https:' is not recognized as an internal or external command
'YN' is not recognized as an internal or external command
```

而那三行原本都只是 `echo` 和 `choice`。

解法：所有中文输出都挪进 `tools/pack.js`。Node 在 Windows 上往控制台写字用的是
`WriteConsoleW`（宽字符 API），**跟当前代码页无关**，所以不管 chcp 是多少都打得对。
bat 只剩「找不到 node」这一句英文兜底 —— 那个分支要是触发了，也就没有 node
来打中文了。

**④ GUI 程序在 PowerShell 里不会等。**

`& WaifuCode.exe --shot` 立刻返回、`$LASTEXITCODE` 是 0，
然后你去检查产物 —— 什么都没有，看着像是程序啥也没干。
其实它才刚启动。要 `Start-Process -Wait`。

### 打包产物自检

`WaifuCode.exe --shot` 会加载模型、依次切四种情绪、各截一张图，然后**自己退出**。
这是验证打包结果最省事的办法：截图不是空白，就说明模型、贴图、表情、
气泡、渲染管线在打包环境里全是通的。

图落在 `DATA_ROOT` 下（免安装版就是 `dist/win-unpacked/data/`）。
开发那只在跑的时候要加 `--user-data-dir=<某个临时目录>` 绕开单实例锁。

## 写 Electron 自检时踩过的坑：后台节流

`tools/test-stage.js` 有阵子**每次跑挂的项目都不一样** —— 这次是动作没退场，
下次是部件透明度没写进去，再下次是帧内采样读到 undefined。

根因不在被测代码，在测试自己的窗口：**Chromium 会把失焦或被遮住的窗口的 rAF 掐到
近乎停止**（实测隐藏窗口 800 毫秒只跑 1 帧）。而这个自检量的全是**逐帧才发生的事**，
于是就成了随机挂。

```js
webPreferences: { backgroundThrottling: false }
```

主进程那个桌宠窗口早就关了这个（不然她失焦时呼吸眨眼会卡成 PPT），
只有测试窗口一直没加。凡是要量「帧里发生了什么」的 Electron 脚本都得关。

另一个同源的坑：**别用「外接框往下 14%」这种写死的比例当点击落点。**
待机动作一直在动她的头，同一个比例这一秒在头上、下一秒就落空。
现在是从上往下扫，找一个 `waifuStage.hit()` 认账的点再点。

## 出了问题

窗口是全透明的，**啥也没出现 ≠ 没启动**。先看 `waifu.log`：

- 有 `模型加载成功` → 渲染没问题，可能只是被别的窗口挡了或位置跑到屏幕外
- 有 `自检 ... 网络层失败` → 模型文件缺了或路径不对
- 有 `表情 xxx 应用=false` → 这个表情名在模型里不存在
- 有 `[term] 终端: （没找到 Windows Terminal…）` → 会回落到老式控制台，功能正常
- 有 `[voice] 丢弃连接重建` → 正常，微软那边掐了闲置连接，她自己重连了
- 什么都没有 → Electron 根本没起来，命令行跑 `npm start` 看报错

终端开出来但立刻报「读不到这个终端任务的参数」：`sessions/terminals/` 被清过了，
窗口里按回车关掉重新派一次就行。

点面板上的终端调不到前面：多半那个窗口已经被你关了（面板上那条会在几十秒内
自动变灰）。如果窗口明明还在，看日志里 `[term] wt focus 没成` 的报错。

> **踩过的坑：PowerShell 脚本要存成带 BOM 的 UTF-8。**
> PowerShell 5.1 读没有 BOM 的 `.ps1` 会按系统 ANSI（中文机器上是 GBK）解码，
> 中文注释直接变成乱码字节，把语法都搞崩 —— 报的还是「第 98 行意外的 `}`」
> 这种完全指不到真凶的错。

> **踩过的坑：PowerShell 会吞掉空字符串参数。**
> 在命令行里测 `claude --tools "" --system-prompt "人设"`，那个空值会被直接吃掉，
> 参数一错位，测出来的结论跟代码里跑的根本不是一回事 ——
> 白白得出「`--system-prompt` 不管用」的错误结论。
> 验证这类事情要用 Node 的 `spawn` 传数组，跟生产代码走同一条路。

想看渲染效果：`npm run shot`。会依次把她推进「平静→害羞→烦躁→得意」
四种情绪并各拍一张（`shot-*.png`），表情调得对不对一目了然。
